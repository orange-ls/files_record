先读这里：每周到底怎么安排

每周按三个时段执行：45 分钟学当周必需概念，90 分钟动手，45 分钟测试与复盘，共 3 小时。这是已经熟悉后端开发时的最低预算，不是保证能按时完成。第 4 个小时补边界和失败用例，第 5 个小时再做选修；忙的一周不看选修，也不跳过验收。平均每周 4 小时约 96 小时，卡住就顺延本周，不堆积下周任务。

每周的文档是主资料，中文视频用来解释概念。视频选看 10–20 分钟即可，算在学习时段内，用它替代部分阅读，而不是额外刷完整课程。这里的分钟数是你的观看预算，不是视频实际时长；没有核实的章节、字幕、免费状态和播放条件不作承诺。没有匹配到合适中文视频的主题，直接用中文文档，不用一门框架大课替代。

每次练习结束，只写清“做了什么、拿什么证明、哪里仍不懂”。验收失败就回到同一任务。能独立解释并通过测试的旧知识直接跳过，不需要重新学习 Python 语法或 CRUD。

只做这个项目，不顺手造平台

项目叫“工单辅助服务”。第一条接口对合成工单做分类、摘要和缺失字段识别；第二条接口从约 20 篇短 Markdown/TXT 文档检索证据，再给出带引用的建议。模型结果只供人工审核，不自动退款、不改订单、不关闭工单。工单和知识库都用人工编写或合法公开资料，不使用公司客户信息。

默认采用 FastAPI、Pydantic v2、HTTPX、pytest/AnyIO、一家模型服务商和 NumPy。你若已有熟悉的 Web 框架，可以沿用，不为学习迁移。模型服务商文档以百炼作中文示例，费用和能力按所选模型实际说明核对；不要求采购。元数据先用 JSONL/本地文件，向量先放本地数组，不引入数据库、队列或向量平台来增加负担。

环境提醒：本次命令行检测到默认 Python 为 3.8.10。规划中的 asyncio.timeout 需要 Python 3.11+，建议在独立项目环境使用 Python 3.12，并核对依赖兼容性。这里没有修改你的 Python、安装依赖或更改系统设置。不要直接照搬新文档代码到旧解释器。

Windows 创建项目环境时，先确认使用的是目标解释器，例如已安装 Python 3.12 时用 py -3.12 -m venv .venv。也可直接运行 .venv\Scripts\python.exe，不必为了激活脚本改系统执行策略。全程不关闭 TLS 校验；网络访问受限时保留离线 fake 模式。

# 问题知识库（Problem Knowledge Base）

本技能为 xinchuang-materiel 项目提供问题解决方案的积累和复用能力。核心理念：**先查后做，做完再存**。

## 工作流程

### 第一步：判断是否为专业性问题

收到用户问题后，先判断问题类型：

- **专业性问题**（需要搜索知识库）：
  - 代码报错、异常堆栈、运行时错误
  - Odoo ORM / 框架相关问题
  - 模块间依赖或集成问题
  - 外部系统对接问题（SAP、CRM、WMS、OA、飞书等）
  - 工作流 / 审批流程问题
  - 数据模型设计问题
  - 前端 OWL 组件问题
  - 部署、性能、权限等运维相关问题
  - 业务逻辑理解和实现问题

- **简单问题**（直接回答，不搜索知识库）：
  - 通用编程语法问题
  - 简单的代码格式化
  - 文件查找、目录结构查询
  - 简单的配置修改

如果是专业性问题，进入第二步。

### 第二步：搜索知识库

1. 读取知识库索引文件：`#[[file:.kiro/skills/knowledge_problem_base/knowledge-base/index.md]]`
2. 根据用户问题的关键词（错误信息、模块名、功能点、技术栈等）在索引中匹配相关条目
3. 如果找到匹配条目，读取对应的解决方案文件获取详细内容
4. 将找到的解决方案呈现给用户，并说明："在知识库中找到了相关的解决方案记录"

### 第三步：解决问题

- **知识库有匹配方案**：优先参考已有方案，结合当前具体情况进行调整和应用
- **知识库无匹配方案**：由 Kiro 自行分析和解决问题

### 第四步：评估是否需要记录

问题解决后，根据以下标准判断是否值得记录到知识库：

**值得记录的情况**：
- 经过多轮排查才定位到的问题
- 涉及项目特有的业务逻辑或架构约定
- 容易反复出现的坑（如模块升级兼容性、外部系统接口变更）
- 解决方案不直观，需要特定步骤或技巧
- 涉及多个模块协作的复杂问题
- 与 Odoo 框架特性相关的非显而易见的问题

**不需要记录的情况**：
- 例如纯对话、方案评估、简单问答、通用知识
- 简单的语法错误或拼写错误
- 通用的 Python/JS 问题，网上容易搜到
- 一次性的配置问题
- Kiro 一步就能解决的简单问题
  
### 第五步：询问用户确认

如果判断需要记录，**必须先询问用户**：

```
本次解决的问题具有一定复杂度和参考价值，建议记录到知识库以便后续遇到类似问题时快速解决。

问题摘要：[简要描述问题]
解决方案要点：[简要描述方案]

是否需要记录到知识库？(y/n)
```

**等待用户明确回复确认后**，才进入第六步。用户未确认前，不得执行记录操作。

### 第六步：记录解决方案

用户确认后，执行以下操作：

1. 在 `knowledge-base/solutions/` 目录下创建解决方案文件，命名格式：`YYYY-MM-DD-简短描述.md`
2. 更新 `knowledge-base/index.md` 索引文件，添加新条目

#### 解决方案文件模板

```markdown
# [问题标题]

## 问题描述
[详细描述问题现象、错误信息、触发条件]

## 影响范围
- 涉及模块：[模块名]
- 涉及文件：[关键文件路径]
- 影响功能：[受影响的业务功能]

## 根因分析
[问题的根本原因]

## 解决方案
[具体的解决步骤和代码修改]

## 关键代码
（关键代码片段）

## 注意事项
[使用此方案时需要注意的点]

## 标签
[用于检索的关键词标签，如：redis, session, 超时, xc_web_login]
```

#### 索引文件格式

索引文件 `knowledge-base/index.md` 采用表格格式，便于快速检索：

```markdown
| 日期 | 问题标题 | 涉及模块 | 关键标签 | 方案文件 |
|------|---------|---------|---------|---------|
| 2026-03-24 | Redis Session 超时 | xc_web_login | redis, session, 超时 | solutions/2026-03-24-redis-session-timeout.md |
```

## 知识库目录结构

```
knowledge_problem_base/
├── SKILL.md                          # 技能定义（本文件）
└── knowledge-base/
    ├── index.md                      # 解决方案索引（快速检索用）
    └── solutions/                    # 解决方案详情
        ├── 2026-03-24-example.md
        └── ...
```

## 搜索策略

搜索知识库时，按以下优先级匹配：

1. **错误信息精确匹配**：用户提供的错误信息或异常类名
2. **模块名匹配**：涉及的 xc_addons 模块名
3. **功能关键词匹配**：业务功能描述（如"审批流程"、"发货单"、"借用申请"）
4. **技术栈关键词匹配**：技术组件（如"Redis"、"OWL"、"Flowable"、"SAP 接口"）

如果索引中没有明确匹配，也可以用 grepSearch 在 solutions 目录中搜索关键词。

# Module-Knowledge Skill 创建规范

本文件定义了为业务模块创建知识库技能（module-knowledge skill）的标准章节结构和目录规范。

---

## 目录结构规范

由于 skills 不支持多层子目录递归，模块知识库技能采用 `{module}--{skill}` 的扁平命名方式：

```
.kiro/skills/
├── {module}--knowledge/         # 模块知识库技能（必须）
│   └── SKILL.md                 # 知识库文档，遵循下方章节结构
├── {module}--integration/       # 模块集成指南（可选）
│   └── SKILL.md
└── {module}--other-skill/       # 其他模块特有技能（可选）
    └── SKILL.md
```

示例：
```
.kiro/skills/
├── dcg_flowable--knowledge/     # 工作流模块知识库
│   └── SKILL.md
├── dcg_flowable--integration/   # 工作流集成开发指南
│   └── SKILL.md
└── xc_borrow--knowledge/        # 样机借用模块知识库
    └── SKILL.md
```


---

## SKILL.md 章节结构（必须严格遵循）

```markdown
---
name: {module}-knowledge
description: {module} {模块中文名}模块知识库，包含{核心能力关键词}的数据模型和业务流程。当开发涉及{触发关键词列表}时，务必使用此技能。
---

# 模块中文名（module_name）

> 一句话描述模块的核心定位和职责。

## 模块概述

用 2-3 段文字描述模块的业务背景、核心能力、与其他模块的关系。

## 核心业务流程

用编号列表描述模块的主要业务流程，每个流程用箭头（→）串联关键步骤：

1. 流程A：步骤1 → 步骤2 → 步骤3 → 步骤4
2. 流程B：步骤1 → 步骤2 → 步骤3

## 数据模型

用表格列出模块的所有核心数据模型：

| 模型名 | 说明 |
|--------|------|
| `model.name` | 模型用途说明 |

## 主要功能模块

用列表描述模块的功能分组，每组用加粗标题 + 冒号 + 功能点：

- **功能组A**：功能1、功能2、功能3
- **功能组B**：功能1、功能2

## 外部集成

用表格列出与外部系统的集成关系。无外部集成时标注"无"。

| 系统 | 集成方式 | 说明 |
|------|----------|------|
| 系统名 | HTTP API / PyRFC / 直连 | 集成用途 |

无外部集成时写：

> 无

## 系统术语

用表格列出模块特有的业务术语：

| 术语 | 说明 |
|------|------|
| 术语名 | 术语解释 |
```

---

## 各章节编写要点

| 章节 | 要点 |
|------|------|
| frontmatter name | 格式：`{module}-knowledge`，如 `xc-flowable-knowledge` |
| frontmatter description | 包含模块名、中文名、核心关键词、触发场景，要"pushy"一些确保触发 |
| 模块概述 | 说清楚模块做什么、服务于谁、与哪些模块有依赖关系 |
| 核心业务流程 | 按业务主线梳理，每条流程是一个完整的端到端场景 |
| 数据模型 | 列出所有 ORM 模型（含 mixin/abstract），模型名用反引号包裹 |
| 主要功能模块 | 按功能域分组，不要逐个列举每个方法 |
| 外部集成 | 标注集成方式（REST API / PyRFC / PostgreSQL 直连 / HTTP API 等） |
| 系统术语 | 只列模块特有术语，通用术语不需要 |

## 信息来源

创建 module-knowledge skill 时，按以下优先级获取信息：

1. 模块的 `__manifest__.py`（模块名、依赖、描述）
2. 模块的 `models/` 目录（数据模型、字段、业务逻辑）
3. 模块的 `controllers/` 目录（API 接口、外部集成）
4. 模块的 `data/` 目录（定时任务、默认数据）
5. 模块的 `views/` 目录（功能模块划分）
6. 已有的模块 README.md（如果存在）

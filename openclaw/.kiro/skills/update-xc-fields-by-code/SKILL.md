# update-xc-fields-by-code — 字段文档自动生成技能

直接读取模块的模型定义文件，提取字段信息，生成或更新 `.kiro/skills/xc_fields/` 下的 markdown 文档。不依赖任何外部脚本，全程由 AI 完成文件读取和写入。

---

## 执行流程

### 第一步：确定目标模块

- 用户指定了模块名 → 只处理该模块
- 用户未指定 → 询问用户，或根据上下文判断

模块目录位于 `xc_addons/<模块名>/`。

### 第二步：找到模型目录

按优先级查找：
1. `xc_addons/<模块名>/models/` （本项目约定，优先）
2. `xc_addons/<模块名>/model/`

列出目录下所有 `.py` 文件（跳过 `__init__.py`）。

### 第三步：逐文件读取并提取字段

对每个 `.py` 文件，读取内容后提取：

- `_name = '...'` → 模型名
- `_description = '...'` → 模型中文描述
- `字段名 = fields.类型(string='中文名', ...)` → 字段列表

**提取规则：**
- 只提取有 `_name` 定义的类（跳过没有 `_name` 的 Mixin/工具类）
- 字段类型包括：`Char`、`Text`、`Html`、`Integer`、`Float`、`Monetary`、`Boolean`、`Date`、`Datetime`、`Binary`、`Image`、`Selection`、`Many2one`、`One2many`、`Many2many`
- `string=` 参数的值即为中文名；若无 `string=` 参数，中文名填 `—`
- 跳过以 `_` 开头的私有属性

### 第四步：生成模块 markdown 文件

输出到 `.kiro/skills/xc_fields/<模块名>.md`，格式如下：

```markdown
# <模块名> 字段中英文对照

> 模块：**<模块名>**　　业务：<业务描述>

---

## `<模型名>` — <模型描述>

> 文件：`xc_addons/<模块名>/model/<文件名>.py`

| 字段名（英文） | 中文名 | 类型 |
|---|---|---|
| `field_name` | 中文名 | Char |
```

每个模型一个 `##` 章节，按文件顺序排列。

### 第五步：更新 skill.md 索引（可选）

如果是全量更新，同步更新 `.kiro/skills/xc_fields/skill.md` 中的：
- 模块索引表（模型数、字段数、文件引用）
- 快速查找表（模型名 → 模块名）

单模块更新时，提示用户如需更新索引可运行全量更新。

## 模块业务描述获取方式

生成文档时，从模块的 `__manifest__.py` 中读取 `name` 字段作为业务描述。

```
xc_addons/<模块名>/__manifest__.py
```

读取其中的 `'name': '...'` 值，例如：

```python
# __manifest__.py
{
    'name': '备件测算系统',
    ...
}
```

则业务描述为 `备件测算系统`。

若 `__manifest__.py` 不存在或无法读取 `name`，则用模块目录名作为兜底。

---

## 注意事项

- 一个 `.py` 文件可能定义多个模型类，每个类单独生成一个 `##` 章节
- 同一字段名在多个类中出现是正常的，不需要去重
- 文件较多时（如 xc_sn 有 50+ 个文件），逐文件处理，不要跳过
- 遇到读取失败的文件，记录跳过原因，继续处理其他文件
- 完成后汇报：处理了多少文件、发现了多少模型、多少字段

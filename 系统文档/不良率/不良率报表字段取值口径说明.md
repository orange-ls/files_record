# 不良率报表字段取值口径说明（按模块分别梳理）

- 适用模块：`xc_addons/xc_defect_rate`（不良率系统）
- 组织方式：按四个报表模型各自独立成章，每章包含「页面下拉框 → 切换后的变化 → 逐字段取值逻辑 → 汇总/窗口口径 → 导出列 → 注意点」，各章自包含，不依赖其他章节。
- 表名、字段名一律使用系统内的中文名称。
- 四个页面共同的交互：下拉框切换只按新条件**重新查询已入库结果**（不重算）；只有页面顶部「刷新」按钮会重算数据并落库。

## 一、维修品质不良率报表（`supply_defect_rate.py`）

### 1.1 页面下拉框与可选值

| 下拉框 | 可选值 | 默认值 | 影响范围 |
| --- | --- | --- | --- |
| 维度切换 | 项目维度、物料维度 | 项目维度 | 决定列表展示列、导出列、分组维度、合计行的组织方式 |

- 选中值随查询上下文传给后端，后端在查询条件中追加「维度 = 当前值」，两个维度的数据互不混用。
- 「刷新」会**同时重算项目维度与物料维度**，不受当前下拉值影响；「导出」「导出报修数据」按当前下拉值决定列与取数范围。

### 1.2 数据准备（「刷新」时执行）

| 中文表名 | 参与的中文字段 | 提供内容 |
| --- | --- | --- |
| 服务器-BOM组件信息 | 项目名称、增配整机项目名、是否项目增配、物料代码、物料描述、物料数量、服务开始时间 | 销量、物料描述 |
| 服务器整机存量信息 | 整机SN、服务开始时间、项目名称、CRM立项编号 | 销售年份、项目名称_溯源、CRM立项编号 |
| 计算维修收发货表 | 报修物料代码、备件大类、项目名称、整机SN、返回件类型、返厂时间、测试结论、服务开始时间 | 报修数量与各故障分类数量 |
| 供应商平均不良率 | 物料代码、供应商平均不良率 | 理论不良率基准值 |
| 重点项目监控NA客户清单 | CRM立项编号 | 是否NA客户（用于邮件告警） |

计算步骤：

1. **销量侧**（服务器-BOM组件信息）：按「服务开始时间」年份 + 物料代码汇总「物料数量」；项目维度下项目归属规则为——「是否项目增配」为“是”时取「增配整机项目名」，为“否”或空时取「项目名称」。物料维度不区分项目，同物料同年度全部项目数量合计。
2. **整机侧**（服务器整机存量信息）：按「整机SN」分组，分别取最大的「服务开始时间」、最大的「项目名称」、最大的「CRM立项编号」。
3. **报修侧**（计算维修收发货表）：「报修物料代码」为空的行剔除；按「报修物料代码 + 整机服务开始时间年份」分组（项目维度再加「项目名称」），统计记录条数与各分类计数。
4. **明细行**：以报修侧为主表，左连接销量侧（项目维度需项目名称一致），再按 物料代码 左连接「供应商平均不良率」，按 CRM立项编号 左连接「重点项目监控NA客户清单」。
5. **合计行**：同一项目（或同一物料）下的全部年度行再聚合一次，销售年份固定写为“汇总”。
6. 两个维度的结果各带维度标记后写入结果表（维修品质不良率报表）。

### 1.3 下拉框切换后的变化

| 变化项 | 项目维度 | 物料维度 |
| --- | --- | --- |
| 查询条件 | 追加「维度 = 项目维度」 | 追加「维度 = 物料维度」 |
| 分组维度 | 项目名称 + 报修物料代码 + 销售年份 | 报修物料代码 + 销售年份（跨项目合计） |
| 时间维度 | 整机「服务开始时间」的年份 | 同左 |
| 聚合方式 | 以报修侧为主表，左连接销量侧 | 同左 |
| 隐藏列 | 「维度」列为内部字段，不展示 | 「维度」列不展示，且「项目名称_溯源」「CRM立项编号」两列隐藏 |
| 合计行组织 | 每个「项目 + 物料」一组合计行 | 每个「物料」一组合计行，并额外做行过滤（见 1.5） |
| 导出列 | 17 列 | 15 列（去掉项目名称_溯源、CRM立项编号） |

### 1.4 展示字段取值逻辑

| 字段中文名 | 来源表中文名 | 来源字段中文名 | 取值方式 / 计算公式 | 显示条件 |
| --- | --- | --- | --- | --- |
| 项目名称_溯源 | 服务器整机存量信息 | 项目名称 | 用报修记录的「整机SN」匹配整机存量信息的「整机SN」，取匹配到的「项目名称」最大值 | 仅项目维度展示；物料维度隐藏 |
| CRM立项编号 | 服务器整机存量信息 | CRM立项编号 | 同上关联方式，取匹配到的「CRM立项编号」最大值 | 仅项目维度展示；物料维度隐藏 |
| 故障件物料号 | 计算维修收发货表 | 报修物料代码 | 直接取报修记录的「报修物料代码」，为空的行不参与统计 | 始终展示 |
| 物料描述 | 服务器-BOM组件信息 | 物料描述 | 按「物料代码 + 服务开始时间年份」匹配（项目维度还需项目名称一致），取最大值；匹配不到为空 | 始终展示 |
| 故障件名称 | 计算维修收发货表 | 备件大类 | 按当前分组取「备件大类」最大值 | 始终展示 |
| 销售年份 | 服务器整机存量信息 | 服务开始时间 | 取「服务开始时间」的 4 位年份；未匹配到整机记录时为空；合计行固定显示“汇总” | 始终展示 |
| 销量 | 服务器-BOM组件信息 | 物料数量 | 「物料数量」求和，条件：物料代码相同、服务开始时间年份 = 销售年份（项目维度再加项目名称一致）；无匹配记录时为空 | 始终展示 |
| 报修数量 | 计算维修收发货表 | —（记录条数） | 满足当前分组条件的记录条数，一条报修记录计 1 | 始终展示 |
| 实际更换 | 计算维修收发货表 | 返回件类型 | 「返回件类型」属于 故障件、工厂补发新件、介质保留 的记录条数 | 始终展示 |
| 实际返厂 | 计算维修收发货表 | 返厂时间 | 「返厂时间」非空的记录条数 | 始终展示 |
| 介质保留 | 计算维修收发货表 | 测试结论 | 「测试结论」= 介质保留 的记录条数 | 始终展示 |
| 未复现故障 | 计算维修收发货表 | 测试结论 | 「测试结论」= 故障件未复现故障 的记录条数 | 始终展示 |
| 实际故障 | 计算维修收发货表 | 测试结论 | 「测试结论」属于 故障件确认故障、新件测试故障、新件存在故障、新件测试正常、介质保留 的记录条数 | 始终展示 |
| 实际不良率 | 由本行数量计算 | — | 实际故障 ÷ 销量 × 100，保留 2 位小数 + `%` | 始终展示 |
| 硬件更换不良率 | 由本行数量计算 | — | 实际更换 ÷ 销量 × 100，保留 2 位小数 + `%` | 始终展示 |
| 供应商理论不良率 | 供应商平均不良率 | 供应商平均不良率 | 按「物料代码 = 故障件物料号」关联取原值（小数）× 100，保留 2 位小数 + `%`；该物料未维护时为空 | 始终展示 |
| 不良比对 | 由本行数量与理论值比较 | — | 销量为空时显示 `/`；否则 实际故障 ÷ 销量 ≤ 供应商理论不良率（小数）→ `低`，大于 → `高`；前端对 `高` 的整行标红 | 始终展示 |

内部字段「是否NA客户」不展示：本行 CRM立项编号 命中「重点项目监控NA客户清单」的 CRM立项编号 即为“是”，否则“否”；仅项目维度计算，用于 NA 客户不良率邮件告警。

### 1.5 合计行与物料维度的行过滤

**合计行**

- 销售年份固定为“汇总”，各数量字段（销量、报修数量、实际更换、实际返厂、介质保留、未复现故障、实际故障）为该组合下全部年度行的求和。
- 三个比率字段按**合计后的数量重新计算**（实际故障合计 ÷ 销量合计），不是各年度比率的平均。
- 项目维度的合计行按「项目 + 物料」形成一行；物料维度的合计行按「物料」形成一行。
- 物料维度的合计行销量、报修数量等被 Python 后处理改写为“被保留下来的年度行之和”（原因见下）。

**物料维度的行过滤（仅物料维度执行）**

1. 按故障件物料号分组，统计该物料下每个 4 位年份出现的行数。
2. 保留条件：报修数量 ≠ 0，或者该年份在这个物料下只出现一次；其余（同一年份在多个项目下重复出现、且报修数量为 0 的行）丢弃，避免同一物料同年份重复展示。
3. 合计行销量改写为保留行的销量之和，与保留下来的明细保持一致。

### 1.6 导出列

| 维度 | 导出列（从左到右） |
| --- | --- |
| 项目维度 | 项目名称_溯源、CRM立项编号、故障件物料号、物料描述、故障件名称、销售年份、销量、报修数量、实际更换、实际返厂、介质保留、未复现故障、实际故障、实际不良率、硬件更换不良率、供应商理论不良率、不良比对 |
| 物料维度 | 故障件物料号、物料描述、故障件名称、销售年份、销量、报修数量、实际更换、实际返厂、介质保留、未复现故障、实际故障、实际不良率、硬件更换不良率、供应商理论不良率、不良比对 |

- 导出取数与页面同一份结果表、同一查询条件；「是否NA客户」不导出。
- 另有「导出报修数据」按钮：按当前勾选行的 故障件物料号（物料维度）或 项目名称（项目维度）回查「计算维修收发货表」的报修明细并导出，与上表的报表列无关。

### 1.7 注意点

- 页面以报修侧为主表：**有报修但无 BOM 销量数据**的组合也会成行，此时销量与三个比率字段为空。
- 三个比率（实际不良率、硬件更换不良率、不良比对）**未对销量为 0 做兜底**：销量为空时结果为空白；销量为 0 时数据库会除零报错，导致整次刷新失败。
- 「供应商平均不良率」按 PC / 服务器 / 笔记本三类分别维护（该表有产品类型字段），本报表关联时**只按物料代码**，未带产品类型。
- 同一整机SN 在多条整机记录中时，项目名称与 CRM立项编号是各自取最大值，可能来自不同记录行。
- 物料维度下合计行若报修数量为 0 且该年份非唯一，会随明细一起被过滤掉。

## 二、逐年在保不良率（`warranty_defect_rate.py`）

### 2.1 页面下拉框与可选值

| 下拉框 | 可选值 | 默认值 | 影响范围 |
| --- | --- | --- | --- |
| 年份模式 | 自然年、汇总第几年 | 自然年 | 决定时间维度、分组键、隐藏列 |
| 维度 | 物料号、捆绑料号、备件大类、备件大类Ⅰ级、产品Ⅱ级分类、产品Ⅲ级分类 | 物料号 | 决定分组字段、维度列名、附加分类列是否展示 |

- 两个下拉值都随查询上下文传给后端，后端在查询条件中追加「年份模式 = 当前值」「维度 = 当前值」。
- 「刷新」会重算全部 **2 种年份模式 × 6 种维度 = 12 种组合**；下拉切换只重查已有结果。
- 「维度」列的表头会按下拉值改名为「物料号」「捆绑料号」等实际维度名称。

### 2.2 数据准备（「刷新」时执行）

**报修分子表**（来源：计算维修收发货表 + 物料基础数据）

| 步骤 | 口径 |
| --- | --- |
| 取数字段 | 计算维修收发货表：报修物料代码、服务开始时间、报修时间、测试结论 |
| 排除条件 | 报修物料代码为空、报修物料代码以 `304-` 开头 |
| 销售年份 | 「服务开始时间」的年份 |
| 报修年份 | 「报修时间」的年份 |
| 第几年 | 报修年份 − 销售年份 + 1 |
| 年份序列 | 对每个「物料 + 销售年份」生成「销售年份 → 当前年份」的连续报修年份序列，未发生报修的年份报修数量记 0 |
| 报修数量 | 该「物料 + 销售年份 + 报修年份」下的记录条数 |
| 实际故障数量 | 同分组下「测试结论」属于 故障件确认故障、新件测试故障、新件存在故障、新件测试正常、介质保留 的条数 |
| 分类字段 | 物料描述、捆绑料号、备件大类、备件大类Ⅰ级、产品Ⅱ级分类、产品Ⅲ级分类，刷新时从物料基础数据按物料代码冗余写入分子表 |

**销量与在保分母表**（来源：BOM总表 + 物料基础数据）

| 步骤 | 口径 |
| --- | --- |
| 取数字段 | BOM总表：物料代码、总数量、服务开始时间、服务结束时间 |
| 排除条件 | 物料代码为空、物料代码以 `304-` 开头 |
| 时间基础 | 销售年份 = 「服务开始时间」年份；在保年份 = 与分子表相同的报修年份序列；第几年算法同分子表 |
| 销量 | 「总数量」求和，条件：物料代码相同、服务开始时间年份 = 销售年份（不区分是否在保） |
| 在保数量 | 「总数量」求和，条件：物料代码相同、服务开始时间年份 = 销售年份、且在保年份 ≤ 「服务结束时间」年份；「服务结束时间」为空时按**当前年份**视为仍在保 |
| 分类字段 | 同分子表，从物料基础数据冗余写入 |

**结果表**：以分子表（报修侧）为主表，按维度字段 + 时间维度左连接分母表；即**只有发生过报修的「物料 × 销售年份 × 报修年份」组合才会出现**，有销量无报修的组合不展示。物料号维度在聚合前对历史料号做归一：`前缀-00后缀`（前缀 2~3 位、后缀 4 位）的物料代码把中段 `-00` 统一改写为 `-10`，分子、分母各自内部归一后再连接，避免同一料号两侧匹配不一致导致数量翻倍。

### 2.3 下拉框切换后的变化

**年份模式切换**

| 变化项 | 自然年 | 汇总第几年 |
| --- | --- | --- |
| 查询条件 | 追加「年份模式 = 自然年」 | 追加「年份模式 = 汇总第几年」 |
| 分组维度 | 维度 + 销售年份 + 自然年份（报修年份） | 维度 + 第几年 |
| 时间维度 | 销售年份、报修年份两个独立列 | 只保留第几年一列 |
| 分子与分母的连接键 | 维度 + 销售年份 + 自然年份 | 维度 + 第几年 |
| 聚合方式 | 分子按维度+销售年份+报修年份求和；分母按维度+销售年份+在保年份求和 | 分子按维度+第几年求和（不同销售年份但同为第 N 年的报修相加）；分母按维度+第几年求和（同理） |
| 隐藏列 | 「第几年」隐藏 | 「销售年份」「自然年份」「销量」隐藏（销量仍已汇总入库，只是不展示） |
| 比率分母 | 在保数量 | 在保数量 |

**维度切换**

| 变化项 | 物料号 | 其他 5 种维度 |
| --- | --- | --- |
| 查询条件 | 追加「维度 = 物料号」 | 追加「维度 = 对应值」 |
| 维度取值 | 物料代码，且做历史料号归一（`-00` → `-10`） | 取对应的捆绑料号 / 备件大类 / 备件大类Ⅰ级 / 产品Ⅱ级分类 / 产品Ⅲ级分类 |
| 维度列名 | 表头显示「物料号」 | 表头显示对应的维度名称 |
| 附加分类列 | 展示「描述」「备件大类」「备件大类Ⅰ级」「产品Ⅱ级分类」「产品Ⅲ级分类」 | 这 5 列隐藏（取值为空） |
| 导出列 | 维度 + 描述 + 时间列 + 数量比率列 + 末尾 4 个分类列 | 维度 + 时间列 + 数量比率列 |

### 2.4 展示字段取值逻辑

| 字段中文名 | 来源表中文名 | 来源字段中文名 | 取值方式 / 计算公式 | 显示条件 |
| --- | --- | --- | --- | --- |
| 维度 | 计算维修收发货表 / BOM总表 / 物料基础数据 | 报修物料代码、物料代码、捆绑料号、备件大类、备件大类Ⅰ级、产品Ⅱ级分类、产品Ⅲ级分类 | 按当前维度下拉取对应字段分组；物料号维度做历史料号归一；该字段为空的行不参与 | 始终展示，表头随维度改名 |
| 描述 | 物料基础数据 | 物料描述 | 按物料代码取「物料描述」最大值 | 仅物料号维度展示 |
| 销售年份 | 计算维修收发货表 | 服务开始时间 | 取「服务开始时间」的年份 | 仅自然年模式展示 |
| 自然年份 | 计算维修收发货表 | 报修时间 | 取「报修时间」的年份 | 仅自然年模式展示 |
| 第几年 | 计算维修收发货表 | 服务开始时间、报修时间 | 报修时间年份 − 服务开始时间年份 + 1 | 仅汇总第几年模式展示 |

| 滚动窗口2 ~ 滚动窗口12 | 同上 | 同上 | 同上，起点依次后移一个月；第 12 个窗口起点为起始年 12 月 | 始终展示，列头为动态区间 |

### 4.5 滚动窗口的计算口径

1. **逐月故障率**：某维度在某自然月 = 该月报修数量 ÷ 该月在保数量 × 100，在保数量为 0 时记 0。
2. **窗口取值**：窗口 i（i = 1~12）覆盖「年份范围起始年」的第 i 月起连续 12 个自然月（跨年），窗口值 = 这 12 个月逐月故障率之和 ÷ 12。
3. **缺失月份**：未来月份（尚未到当前月）或该维度该月无数据，一律按 0 计入，因此窗口值恒为 12 个月的平均值，不按实际有数据的月数折算。
4. **展示格式**：保留 2 位小数后追加 `%`。

| --- | --- |
| 滚动窗口1 | 2025/01 - 2025/12 |
| 滚动窗口2 | 2025/02 - 2026/01 |
| …… | …… |
| 滚动窗口11 | 2025/11 - 2026/10 |
| 滚动窗口12 | 2025/12 - 2026/11 |

### 4.6 导出列

| 导出列（从左到右） |
| --- |
| 维度（列头为「物料号」或对应的维度名称）、滚动窗口1、滚动窗口2 …… 滚动窗口12 |

- 导出与页面同一份结果表、同一组查询条件（年份范围、维度）。

### 4.7 注意点

- 页面以报修侧为主表：只有**近三年内发生过报修**的物料或分类取值才会成行，无报修的物料不出现。
- 在保数量只统计「服务结束时间」有值的 BOM 记录，**服务结束时间为空的记录不命中任何月份**、不计入在保（与逐年在保不良率「为空视为仍在保」的规则相反）。
- 非物料号维度使用的是中间表阶段按原始料号汇总的在保数量，只有物料号维度才回源按归一料号重算。
- 窗口值依赖“当前月”边界：中间表只刷新到当前月，当前月之后的月份按 0 参与平均，因此越靠近当前年的窗口数值越低。

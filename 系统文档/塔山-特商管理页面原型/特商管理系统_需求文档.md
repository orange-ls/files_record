# 特商管理系统需求文档

> 版本：1.0  
> 编制日期：2026-10-26  
> 适用范围：现有特商管理系统已实现的业务功能  
> 文档性质：业务需求与页面操作说明，不是技术设计文档，也不是后续改造计划  
> 依据：`xc_addons/xc_special_business` 当前代码中的菜单、视图、模型、流程定义、权限配置和页面脚本  
> 说明：`docs/superpowers/plans` 下的旧计划只作为背景参考，本文所有口径以当前代码实际行为为准

## 1. 文档说明

### 1.1 目的

本文把特商管理系统当前已经实现的业务规则、页面入口、页面操作、审批流程、状态变化和数据权限整理成一份可评审、可验收、可交付的需求文档，供业务、测试、实施和后续开发共同使用。，

### 1.2 范围

覆盖除“测试机管理”以外的全部功能页面，包括：

- 特商申请
- 特商延期
- 特商激活
- SO管理
- 下单申请
- 我的申请 → 我的提交
- 我的待办 → 待我处理、我已处理
- 日志 → 审批日志
- 配置 → 主板型号、审批用户组、部署流程

不覆盖：

- 测试机管理；
- 销帮帮系统本身的功能改造；
- Flowable 引擎本身的安装、运维和流程建模器；
- 历史数据迁移方案；
- 报价系统、财务系统等外部系统的内部实现。

### 1.3 阅读约定

- “页面”指用户从菜单进入或从单据行打开的界面。
- “单据”指特商申请、延期申请、激活申请、SO申报、下单申请。
- “台账”指特商申请审批完成后生成的额度与有效期记录，是延期、激活的数据来源。
- “商机池”指从销帮帮商机同步出来的只读商机列表，是 SO申报、下单申请的发起入口。
- “审批中”同时涉及业务状态和审批状态两个维度，页面上的状态条以审批状态为准，列表中的业务状态单独展示。

## 2. 系统总览

### 2.1 业务对象关系

```text
销帮帮商机
   └─ 商机池（只读镜像）
        ├─ 发起 SO申报  → SO申报单
        └─ 发起下单申请 → 下单申请单

特商申请单
   └─ 审批通过 + 商务回填
        └─ 特商台账（编码、有效期、型号额度）
             ├─ 发起延期 → 延期申请单
             └─ 发起激活 → 激活申请单

下单申请单 --按“特商编码”文本反查--> 特商台账
```

关键关系：

1. 特商申请是台账的唯一来源。申请审批完成并完成商务回填后，系统按申请明细生成台账和额度明细。
2. 延期、激活都挂在台账上，不直接挂在申请单上。延期页、激活页的列表底表都是台账。
3. SO申报、下单申请从商机池发起，不要求先有特商申请；只有下单申请在“是否含特商”为是时，才需要填写与台账一致的特商编码。
4. 下单申请和台账之间没有外键，按“下单申请的特商编码 = 台账编码”匹配；匹配不上不会阻止下单，但台账侧反查会看不到该单。
5. 我的提交是五类单据的只读聚合视图，不在这里创建、修改或审批单据。

### 2.3 统一状态口径

五类单据都存在“审批状态”和“业务状态”，但字段取值不完全相同。

| 单据 | 业务状态 | 取值 |
| --- | --- | --- |
| 特商申请 | 业务状态 | 草稿、待生效、已生效、已作废 |
| 延期申请 | 办理状态 | 草稿、审批中、已确认、已取消 |
| 激活申请 | 办理状态 | 草稿、审批中、已确认、已取消 |
| SO申报 | 业务状态 | 草稿、办理中、已完成、已作废 |
| 下单申请 | 业务状态 | 草稿、办理中、已完成、已作废 |

五类单据共用的审批状态：

| 审批状态 | 含义 |
| --- | --- |
| 无审核 | 还未发起流程 |
| 审核中 | 流程正在运行 |
| 已审核 | 流程已通过 |
| 已驳回 | 审批人作废或流程拒绝 |
| 已撤回 | 申请人撤回或放弃草稿后的终止态 |

注意：

- “放弃草稿”和“撤回申请”都进入终止态，但前者只适用于从未提交过的草稿，后者只适用于审批中的单据。
- “作废”是审批人的动作，会终止流程并留下审批记录；不要和申请人的“放弃草稿”混用。
- “退回”不是终止，流程实例保留，单据回到指定节点继续办理。
- 延期和激活的“已确认”表示商务已经完成回填，不代表单据还可以修改。

## 3. 角色与权限

### 3.1 角色划分

系统通过“菜单组 + 数据组 + 审批组”三层控制权限。

| 角色/用户组 | 主要职责 | 关键权限 |
| --- | --- | --- |
| 特商销售组 | 发起申请、延期、激活、SO、下单 | 全部业务菜单；可发起本人负责或共享的台账；不可见价格、SO敏感数据、配置 |
| 特商商务组 | 查看全量业务数据、配置 | 销售组权限 + 价格 + SO敏感数据 + 配置菜单 |
| 特商产品组 | 查看全量业务数据、配置 | 与商务组相同的业务数据范围；不直接办理审批节点 |
| 特商商务审批组 | 商务经理审批、商务回填、延期/激活确认和回填、SO/下单商务节点 | 审批菜单和对应业务单据的审批权限，不自动获得配置权限 |
| 特商产品审批组 | 产品经理审批 | 产品审批节点 |
| 特商销售组长组 | SO/下单的销售组长审批 | 销售组权限 + 审批菜单；组长本人发起时可跳过组长节点 |
| 特商SO销售负责人组 | SO的销售负责人审批 | SO菜单 + 审批菜单 |
| 特商风控审批组 | SO/下单的风控负责人审批、加签 | SO/下单菜单 + 审批菜单 |
| 特商售前配置审核组 | 下单的售前配置审核 | 下单菜单 + 审批菜单 |
| 特商下单审批组 | 下单的“回填审批”节点 | 下单菜单 + 审批菜单 |
| 特商配置管理员 | 维护主板型号、审批用户组、部署流程 | 全部审批菜单 + 配置菜单 |

管理员和超级用户默认拥有全部权限。

### 3.2 菜单可见性

- 根菜单“特商管理系统”由根菜单组控制。
- 每个业务菜单由对应菜单组控制；拥有子菜单权限的用户会自动获得根菜单可见性。
- “我的申请”本身只是目录；“我的提交”“我的待办”“审批日志”分别由申请菜单组、审批菜单组控制。
- 配置菜单只对配置管理员开放。
- 菜单组只决定“能不能看到入口”，不决定“能不能操作某一条数据”；具体数据范围由记录规则控制。

### 3.3 数据可见性

| 数据对象 | 销售组 | 数据组/审批组/配置 |
| --- | --- | --- |
| 特商申请 | 只看本人负责的申请 | 全量 |
| 商机池 | 本人负责、未分配、已发起 SO/下单的商机 | 全量 |
| SO申报 | 本人负责 + 未分配的单据；加签人只读 | 全量 |
| 下单申请 | 本人负责 + 未分配的单据；加签人只读 | 全量 |
| 特商台账 | 全部台账可读，但只有负责人、共享人、管理员可发起 | 全量 |
| 延期申请 | 销售组内可见 | 全量 |
| 激活申请 | 销售组内可见 | 全量 |
| 我的提交 | 只看本人提交的单据 | 商务、产品、商务审批、配置看全量 |
| 主板型号 | 只读 | 配置管理员可维护 |
| 审批日志 | 审批菜单组可查看五类流程的审批历史 | 同左 |

补充规则：

1. 表中“全量”的组按对象不完全相同：特商申请、台账、延期、激活、我的提交主要由商务、产品、商务审批、配置管理员看全量；SO申报还包含销售组长、SO销售负责人、风控、产品审批等节点组；下单申请还包含销售组长、风控、售前配置审核、下单审批等节点组。具体以第 8、9 章为准。
2. 申请、SO、下单、台账、延期、激活的可见范围都在记录规则中实现；页面按钮的显隐不能替代服务端校验。
3. 商机池“已提交”的行对其他销售仍然可见，避免第一个销售认领后其他人完全看不到状态；但能否打开原单据仍由原单据的记录规则控制。
4. 加签人可能不是单据的销售负责人，系统通过单据上的“加签人”关系提供只读可见性；加签人不能修改业务单据。
5. SO、下单的“未分配”按公共池处理，任何销售都可能看到；谁先提交审批谁成为认领人，草稿阶段不产生认领人。

### 3.4 字段级权限

| 字段区域 | 可见/可编辑范围 |
| --- | --- |
| 特商申请的价格、折扣 | 仅“特商价格可见权限”组可见；销售不可见也读不到 |
| SO申报的成本、毛利、主板金额、其他金额、是否已下单、欠账信息、历史订单信息 | 仅“SO敏感数据可见权限”组可见 |
| 下单申请的备货价审单号、备货流程单号、1Y号、金额 | 仅商务审批组、商务组、产品组、下单审批组等配置的组可见；销售不可见 |
| 回填字段 | 只在对应回填节点、且当前用户是节点办理人时才可编辑 |

### 3.5 服务端兜底

以下情况即使绕过页面按钮，服务端也必须拒绝：

- 非申请人提交、放弃或撤回单据；
- 非当前节点办理组审批、退回、作废；
- 非回填节点修改回填字段；
- 非台账负责人/共享人发起延期或激活；
- 非销售组发起 SO/下单；
- 加签任务作废整张单据或继续加签。

## 4. 通用业务规则

### 4.1 单号规则

| 单据 | 前缀 | 生成时机 |
| --- | --- | --- |
| 特商申请 | `SQ` | 创建申请时生成 |
| 延期申请 | `YQ` | 创建延期申请时生成 |
| 激活申请 | `JH` | 创建激活申请时生成 |
| 下单申请 | `XD` | 创建下单申请时生成 |
| SO申报 | `SO` | 点击“提交审批”时生成；草稿阶段单号为空 |

规则：

- 格式为“前缀 + 年月日 + 四位流水”，例如 `SQ202610260001`。
- 单号全局唯一；当天流水按已有最大号递增。
- 单号由系统生成，页面只读，不接受手工修改。

### 4.2 提交与重新提交

- 只有申请人本人或台账共享人代提交的申请人/代提交人可以提交。
- 提交前系统先保存页面内容，再启动或恢复审批流程。
- 首次提交会创建流程实例，单据进入“审核中”；同时记录首次提交时间、最近提交时间和提交版本。
- 被退回“销售修改”的单据再次提交时，系统完成原有的“销售修改”任务，不会重复创建一个新的流程实例。
- 已撤回、已放弃、已作废的单据不能再次提交；需要重新发起一张新单。
- 销售组长发起 SO 或下单申请时，流程跳过“销售组长审批”节点；该标识由系统写入，用户不能手工修改。

### 4.3 放弃草稿、撤回、退回、作废

| 动作 | 操作人 | 适用状态 | 对流程的影响 | 对业务状态的影响 | 是否还能重提 |
| --- | --- | --- | --- | --- | --- |
| 放弃草稿 | 申请人 | 从未提交，审批状态为无审核 | 不启动流程 | 申请/SO/下单一律作废；延期/激活取消 | 不能，重新发起 |
| 撤回申请 | 申请人 | 审批中 | 终止并删除运行中的流程实例，关闭本地待办 | 申请/SO/下单一律作废；延期/激活取消 | 不能，重新发起 |
| 退回 | 当前节点审批人 | 审批中 | 流程实例保留，回到指定节点 | 业务状态保持原状 | 可以，由销售修改后重新提交 |
| 作废 | 当前节点审批人 | 审批中 | 终止流程并关闭剩余任务 | 申请/SO/下单作废；延期/激活取消 | 不能，重新发起 |

补充：

- 激活单在放弃、撤回、退回、作废前会释放已经占用的额度；重新提交时重新校验并占用。
- 延期单放弃、撤回、作废不会改变台账到期日和延期次数。
- 作废会写入审批历史，意见显示“作废”，不会沿用默认的“同意”。
- 已被作废的单据仍保留在“我的提交”中，状态显示为取消或作废；草稿被放弃的单据因为从未提交，不进入“我的提交”。

### 4.4 加签

- 加签只在 SO申报、下单申请的“风控负责人”节点开放；特商申请、延期、激活不支持加签。
- 当前办理人点击“加签”，弹窗中填写加签人（可搜索、多选）和说明；加签人范围限定为启用、非门户、特商销售组成员，且不能选择自己。
- 加签会创建 Flowable 子任务，同时在本地生成一条待办；加签人在“待我处理”中可以看到。
- 加签人打开单据后只能看到只读业务内容，并点击“完成加签”结束自己的子任务。
- 加签人不能作废整张单据，不能继续加签，也不能退回。
- 原办理人必须等所有加签任务完成后才能继续“通过”“退回”或“作废”。
- 同一节点不允许重复加签，已存在未完成加签任务时系统会拦截。

### 4.5 审批任务

- 审批任务由 Flowable 生成，统一在“我的待办”下查看；页面只作为任务入口，不提供脱离业务单据的审批表单。
- “待我处理”默认只显示分派给当前用户的任务，匹配“指定处理人、候选用户、候选组”。
- 当前任务尚未被认领时，节点办理组成员可以看到业务单据并办理；办理时系统会完成认领。
- “我已处理”只显示当前用户已经完成的特商流程任务。
- 审批日志显示五类流程的历史记录，不显示测试机等其它流程。
- 审批任务按流程类型区分：特商申请、延期、激活、下单申请、SO申报；菜单只显示这五类。

### 4.6 附件与导出

- 附件统一用文件上传控件，支持多文件。
- 特商申请附件：询价邮件、申请表、配置单等，提交至少一份。
- 延期材料、激活材料、下单申请的普通申请材料按各自页面要求上传。
- OEM 项目真实性验证表独立于普通申请材料，不阻塞提交与回填。
- 特商申请列表提供“导出Excel”，默认导出当前列表列，排除审批状态、附件和审批历史；范围是当前筛选命中的全部记录。
- 商机池列表的导出使用当前列表列，排除操作列；范围同样受记录规则限制。

## 5. 特商申请

### 5.1 页面定位与入口

- 菜单：特商管理系统 → 特商申请。
- 页面用途：销售新建特商申请，维护商机信息、主板明细和申请材料，提交审批并跟踪回填结果。
- 该页面是特商台账的源头；申请未审批完成前不会生成台账。

### 5.2 列表页

列表顶部按钮：

- 新增申请：打开空白申请表单；列表本身不提供原生“创建”按钮。
- 导出Excel：按当前筛选结果导出当前列。

列表列：

| 列 | 说明 |
| --- | --- |
| 申请单号 | 系统生成 |
| CRM名称、CRM编码 | 商机基础信息 |
| SJ商机编码、SJ商机名称 | 华为侧商机标识 |
| 产品类型 | 由主板明细汇总 |
| 申请台套数 | 由明细台套数汇总 |
| 特商编码 | 商务回填后显示 |
| 价格、折扣 | 默认收起，仅价格权限组可见 |
| 审批状态 | 无审核、审核中、已审核、已驳回、已撤回 |
| 业务状态 | 草稿、待生效、已生效、已作废 |
| 申请时间 | 创建时间 |

搜索与筛选：

- 支持按申请单号、CRM名称/编码、SJ商机编码/名称、特商编码、产品类型、审批状态搜索。
- 常用筛选：未提交、审批中、已通过、已作废、已放弃草稿、已撤回、已生效、待生效、待我处理、我提交的。
- 可按销售负责人分组。

行操作：

- 点击行进入申请详情；已提交、审批中、已生效的申请打开后按权限只读。

### 5.3 详情页

页面结构：

1. 顶部状态条：审批状态。
2. 基本信息：申请单号、CRM名称、CRM编码、SJ商机编码、SJ商机名称、华为一线负责人+编码、华为客户经理+编码、申请台套数、销售负责人。
3. “主板明细”页签：每行一个产品类型、主板型号、台套数；可增加、删除明细行。
4. “附件”页签：申请材料，至少一份。
5. “特商信息回填”页签：特商编码、特商开始时间、特商结束时间、价格、折扣、回填人、回填时间。
6. “审批历史”页签：节点、处理人、到达时间、完成时间、结果、意见。

字段规则：

| 字段 | 维护方式 | 规则 |
| --- | --- | --- |
| 申请单号 | 系统 | 自动生成，只读 |
| CRM名称/编码、SJ商机、华为负责人 | 销售 | 提交前必填 |
| 产品类型 | 明细带出 | 选型号后自动带出；同一行型号必须属于该产品类型 |
| 主板型号 | 销售选择 | 只能选启用的型号；同一申请中不能重复 |
| 台套数 | 销售填写 | 正整数；由明细汇总到主表 |
| 申请台套数 | 系统汇总 | 只读 |
| 特商编码 | 商务回填 | 提交后由商务在回填节点填写；去首尾空格并转大写；全系统唯一 |
| 特商开始/结束时间 | 商务回填 | 结束时间不得早于开始时间 |
| 价格 | 商务回填 | 不能为负数；0 表示 0 元特商 |
| 折扣 | 商务回填 | 小数填写，0.85 表示 85%；0 表示未填，非 0 时必须在 (0, 1] |
| 回填人/时间 | 系统 | 保存或完成回填时记录 |

业务权限：

- 销售只能看到本人负责的申请；商务、产品、商务审批、销售组长、配置管理员可看全量。
- 销售看不到价格和折扣字段；商务、产品、商务审批组可见。
- 只有申请人本人可以修改销售字段；审批人不能替销售改内容。
- 只有“商务回填”节点的办理人可以修改回填字段；其它审批节点只读。
- 已生效、已作废的申请永久锁定。

### 5.4 页面操作

| 操作 | 出现条件 | 行为 |
| --- | --- | --- |
| 提交审批 | 草稿、被退回到销售修改、未终止 | 校验必填项后保存并启动/恢复流程 |
| 放弃草稿 | 申请人、未提交、未终止 | 单据作废，不启动流程 |
| 撤回申请 | 申请人、审批中、未终止 | 终止流程，单据作废 |
| 通过 | 当前节点办理人；特商申请在商务回填节点也用“通过”完成回填 | 审批通过；在商务回填节点会先校验并记录回填信息，然后结束流程 |
| 暂存回填 | 当前节点为商务回填且本人办理 | 保存回填内容，不推进流程；不是“通过”的前置条件 |
| 退回销售 | 当前节点允许退回销售 | 流程回到“销售修改”，流程实例保留 |
| 退回商务 | 当前节点允许退回商务 | 流程回到商务经理审批 |
| 退回产品 | 当前节点允许退回产品 | 流程回到产品经理审批 |
| 作废 | 当前节点办理人，且不是加签任务 | 终止流程，单据作废 |
| 查看审批历史 | 任何人按权限查看 | 显示本单全部任务记录 |

按钮显隐由服务端计算，不只看页面状态；直接调用接口也会校验角色和节点。

### 5.5 提交校验

点击“提交审批”时一次性列出所有问题：

- CRM名称不能为空；
- CRM编码不能为空；
- SJ商机编码不能为空；
- SJ商机名称不能为空；
- 华为一线负责人不能为空；
- 华为客户经理不能为空；
- 主板明细至少一行；
- 每条明细必须带出产品类型；
- 每条明细台套数必须为正整数；
- 附件至少一份；
- 同一申请中主板型号不能重复。

保存草稿不做上述完整性校验，允许先保存后补填。

### 5.6 商务回填校验与生效

商务在“商务回填”节点可以点“暂存回填”保存，也可以直接点“通过”完成回填；“暂存回填”只保存当前内容，不校验完整性；点“通过”时会触发以下校验：

- 特商编码不能为空；
- 特商开始时间不能为空；
- 特商结束时间不能为空；
- 结束时间不能早于开始时间；
- 主板明细不能为空；
- 特商编码规范化后不能与其它台账重复；
- 价格不能为负数；
- 折扣非 0 时必须在 0 到 1 之间。

点“通过”即完成回填；完成后流程结束，系统生成台账：

- 台账编码继承特商编码；
- 台账销售负责人继承申请销售负责人；
- 台账有效期继承特商开始/结束时间；
- 按申请明细生成额度明细，获批数量等于申请台套数；
- 申请业务状态变为“已生效”。

### 5.7 审批流程

```text
销售提交
  → 商务经理审批
  → 产品经理审批
  → 商务回填
  → 完成，生成台账
```

退回关系：

- 商务经理审批 → 退回销售；
- 产品经理审批 → 退回商务、退回销售；
- 商务回填 → 退回商务、退回产品、退回销售。

被退回销售后，单据进入“销售修改”，销售修改内容后重新提交；流程实例保留，不新建流程。

## 6. 特商延期

### 6.1 页面定位与入口

- 菜单：特商管理系统 → 特商延期。
- 页面用途：查看已生效台账的到期情况，对即将到期或已到期的特商发起延期。
- 列表底表是“特商台账”，不是延期申请单；延期申请从台账行的“发起延期”进入。

### 6.2 列表页

默认筛选：

- 默认只显示“当月到期”的台账；用户可以手动取消筛选查看全部。

列表列：

| 列 | 说明 |
| --- | --- |
| 操作 | 发起延期/重新发起；共享 |
| 特商编码 | 台账编码 |
| 项目名称 | 来源申请的 CRM 名称 |
| 到期日 | 当前有效期 |
| 产品类型 | 台账明细汇总 |
| 获批台套数 | 台账总量 |
| 剩余可激活 | 当前可激活数量 |
| 延期次数 | 累计已确认的延期次数 |
| 最近延期时间 | 上次完成延期的日期 |
| 状态 | 有效、已过期 |

页面行为：

- 列表不提供新增、删除；行点击和回车不进表单。
- 所有操作通过第一列按钮完成。
- “发起延期”按钮只对台账负责人、共享人、管理员可点；其他人看到灰色按钮。
- “共享”按钮对负责人、商务、配置管理员等有共享权限的人显示；点击后打开弹窗，台账只读展示，选择“共享给”人员后确定或取消。共享人范围同样限定为启用、非门户、特商销售组成员。
- 只能在负责人或共享人的台账上发起；共享人代发起时，申请人仍是台账负责人，实际发起人记录为“代提交人”。

搜索与筛选：

- 支持按特商编码、项目名称、来源申请、销售负责人搜索。
- 筛选：当月到期、已过期、有效期内、有延期记录。
- 分组：到期月、销售负责人。

### 6.3 延期申请详情

打开方式：

- 点击台账行的“发起延期”。
- 如果该台账已有草稿或审批中的延期申请，直接打开原单，不新建；避免同一台账出现多张未完成延期单。
- 没有未完成申请时才打开空白延期表单。

页面结构：

1. 顶部状态条：审批状态。
2. 特商信息：关联台账、特商编码、项目名称、产品类型。
3. 延期信息：原到期日、期望延期至、延期天数、实际确认到期日、申请人、代提交人、确认人、确认时间、申请单号。
4. “延期材料”页签：附件。
5. “办理意见”页签：文本。
6. “延期日志”页签：当前台账下全部延期记录，包括历史已确认和已取消的记录。
7. “审批历史”页签：本单审批轨迹。

字段规则：

| 字段 | 维护方式 | 规则 |
| --- | --- | --- |
| 关联台账 | 系统带出 | 草稿阶段可以更换；提交后不可更换 |
| 原到期日 | 系统快照 | 创建和提交时取台账当前到期日；后续台账变化不自动改快照 |
| 期望延期至 | 销售填写 | 必填，必须晚于原到期日 |
| 延期天数 | 系统计算 | 期望日期与原到期日的天数差 |
| 实际确认到期日 | 商务回填节点填写 | 完成回填前必填 |
| 申请人 | 系统 | 固定为台账负责人；共享人代提交不改申请人 |
| 代提交人 | 系统 | 当前操作人不是台账负责人时记录 |
| 确认人/确认时间 | 系统 | 完成回填时记录 |

### 6.4 页面操作

| 操作 | 出现条件 | 行为 |
| --- | --- | --- |
| 提交 | 草稿、或被退回到销售修改 | 校验期望日期和唯一性后启动/恢复流程 |
| 放弃草稿 | 申请人、未提交 | 取消单据，台账不变 |
| 撤回申请 | 申请人、审批中 | 终止流程，取消单据 |
| 确认延期 | 商务确认节点办理人 | 审批通过，进入商务回填 |
| 完成回填 | 商务回填节点办理人 | 校验实际日期并回写台账，流程结束 |
| 退回销售 | 当前节点允许退回销售 | 回到销售修改，流程保留 |
| 作废 | 当前节点办理人 | 终止流程，单据取消 |
| 查看审批历史 | 按权限 | 显示本单审批记录 |

注意：

- 延期单不允许直接调用通用“通过”；必须使用“确认延期”和“完成回填”，否则台账不会更新。
- “确认延期”只推进流程，不写台账；“完成回填”才写实际到期日、延期次数和最近延期时间。
- 完成回填时如果台账当前到期日已经不等于本单的“原到期日”，系统会拒绝，提示先核对台账或退回重发，避免两次延期互相覆盖。

### 6.5 提交校验

- 必须关联台账；
- 当前用户必须是台账负责人、共享人或管理员；
- 申请人必须是台账负责人；共享人代提交时保留原申请人；
- 期望延期日期必填；
- 期望延期日期必须晚于原到期日；
- 同一台账同时只能有一张草稿或审批中的延期申请；
- 已撤回、已放弃、已作废的延期单不能重新提交。

### 6.6 完成回填规则

- 实际确认到期日必填；
- 台账当前到期日必须仍等于本单原到期日；
- 台账到期日更新为实际确认到期日；
- 延期次数加 1；
- 最近延期时间更新为当天；
- 如果台账来自特商申请，申请单的特商结束时间同步更新；
- 单据办理状态变为“已确认”，记录确认人和确认时间；
- 流程结束。

### 6.7 审批流程

```text
销售提交
  → 商务确认
  → 商务回填
  → 已确认
```

退回关系：

- 商务确认 → 退回销售；
- 商务回填 → 退回商务、退回销售。

### 6.8 台账详情（延期/激活共用）

台账详情用于查看额度、有效期和历史记录，入口不在菜单上单独列出，而是作为延期、激活页面的底层数据视图。

页面结构：

1. 顶部操作：发起延期、发起激活、共享。
2. 基本信息：来源申请、项目名称、销售负责人、共享人、产品类型。
3. 有效期：生效日期、到期日、期初已激活数、期初延期次数、累计延期次数、最近延期时间。
4. 额度汇总：获批总台套数、已激活台套数、待确认占用、剩余可激活。
5. “额度明细”页签：主板型号、型号快照、产品类型、获批数量、已激活数量、待确认占用、可用数量。
6. “延期历史”页签：该台账全部延期记录。
7. “激活历史”页签：该台账全部激活记录。
8. “关联下单”页签：按特商编码反查关联的下单申请。

额度口径：

- 总获批 = 所有额度行获批数量之和；
- 已激活展示值 = 所有额度行已激活数量之和 + 期初已激活数；
- 待确认占用 = 所有额度行提交后尚未结转的数量；
- 剩余可激活 = 总获批 - 额度行已激活数量 - 待确认占用，最小为 0；期初已激活数只参与展示，不参与当前可激活额度扣减；
- 台账状态按到期日与当天比较，过期显示“已过期”，否则“有效”。

## 7. 特商激活

### 7.1 页面定位与入口

- 菜单：特商管理系统 → 特商激活。
- 页面用途：对已生效且未过期的特商台账发起额度激活，按型号选择激活数量。
- 列表底表与延期页相同，都是特商台账；激活申请从台账行的“发起激活”进入。

### 7.2 列表页

列表列：

| 列 | 说明 |
| --- | --- |
| 操作 | 发起激活/重新发起；共享 |
| 特商编码 | 台账编码 |
| 项目名称 | 来源申请的 CRM 名称 |
| 到期日 | 当前有效期 |
| 产品类型 | 台账明细汇总 |
| 获批台套数 | 台账总量 |
| 已激活 | 已结转的数量 |
| 待确认占用 | 审批中的激活申请占用数量 |
| 剩余可激活 | 当前还可申请激活的数量 |
| 状态 | 有效、已过期 |

页面行为：

- 默认不按到期月过滤；可按筛选条件查看已过期、有效期内等。
- 行点击和回车不进入表单；所有操作通过第一列按钮完成。
- 只有台账负责人、共享人、管理员可以发起激活。
- 共享人代发起时，申请人仍是台账负责人，实际发起人记录为“代提交人”。
- 若台账已过期，点击发起激活会提示先完成延期；若剩余可激活为 0，提示无可激活额度。

搜索与筛选：

- 与延期页共用台账搜索：特商编码、项目名称、来源申请、销售负责人。
- 筛选：当月到期、已过期、有效期内、有延期记录。
- 分组：到期月、销售负责人。

### 7.3 激活申请详情

打开方式：

- 点击台账行的“发起激活”。
- 已有草稿或审批中的激活申请时，直接打开原单；没有才新建。
- 新建时系统按该台账的额度明细自动铺开每个型号一行，用户不需要也不能手工新增/删除型号行。

页面结构：

1. 顶部状态条：审批状态。
2. 特商信息：关联台账、特商编码、项目名称、到期日。
3. 申请信息：本次激活总数、申请人、代提交人、确认人、确认时间、申请单号、额度是否已占用。
4. “激活明细”页签：型号、产品类型、可用数量（默认收起）、是否激活、本次激活数量。
5. “激活材料”页签：附件。
6. “办理意见”页签：文本。
7. “审批历史”页签：本单审批轨迹。

明细规则：

- 明细行由台账自动带出，不允许手工增行、删行；
- 默认全部不勾选、数量为 0；
- 勾选“是否激活”后，本次激活数量必须为正整数；
- 不勾选时数量自动清零；
- 每个型号在该申请中只能出现一行；
- 可用数量只作参考，真实校验在提交时按台账行加锁后执行。

字段规则：

| 字段 | 维护方式 | 规则 |
| --- | --- | --- |
| 关联台账 | 系统带出 | 草稿可以更换；提交后不可更换 |
| 本次激活总数 | 系统汇总 | 只勾选行的数量之和 |
| 申请人 | 系统 | 固定为台账负责人 |
| 代提交人 | 系统 | 共享人操作时记录 |
| 确认人/确认时间 | 系统 | 完成回填时记录 |
| 是否激活 | 销售勾选 | 至少勾选一行 |
| 本次激活数量 | 销售填写 | 勾选行必须大于 0；不能超过该型号可用额度 |

### 7.4 页面操作

| 操作 | 出现条件 | 行为 |
| --- | --- | --- |
| 提交 | 草稿、或被退回到销售修改 | 校验额度和有效期，占用额度，启动/恢复流程 |
| 放弃草稿 | 申请人、未提交 | 取消单据，不占用额度 |
| 撤回申请 | 申请人、审批中 | 终止流程，释放本次占用 |
| 确认激活 | 商务确认节点办理人 | 审批通过，进入商务回填，不结转额度 |
| 完成回填 | 商务回填节点办理人 | 将占用转为已激活，流程结束 |
| 退回销售 | 当前节点允许退回销售 | 释放占用，回到销售修改 |
| 作废 | 当前节点办理人 | 终止流程，释放占用，单据取消 |
| 查看审批历史 | 按权限 | 显示本单审批记录 |

注意：

- 激活单不允许直接调用通用“通过”；必须使用“确认激活”和“完成回填”，否则额度不会结转。
- “确认激活”只推进流程，不改变已激活数量；“完成回填”才把待确认占用转为已激活。
- 退回销售、放弃草稿、撤回、作废都会释放占用；重新提交会重新校验并占用。

### 7.5 提交校验

- 必须关联台账；
- 当前用户必须是台账负责人、共享人或管理员；
- 申请人必须是台账负责人；
- 台账未过期；
- 至少勾选一个型号；
- 勾选行的数量必须大于 0；
- 明细行必须属于当前台账；
- 每个型号本次数量不能超过当前可用额度；
- 同一台账同时只能有一张草稿或审批中的激活申请；
- 已撤回、已放弃、已作废的激活单不能重新提交。

### 7.6 额度占用与结转

| 阶段 | 额度变化 |
| --- | --- |
| 提交前 | 不占用 |
| 提交成功 | 待确认占用增加，已激活不变 |
| 退回销售 | 待确认占用释放 |
| 商务确认 | 不改变额度 |
| 完成回填 | 待确认占用减少，已激活增加 |
| 撤回/放弃/作废 | 待确认占用释放 |

系统在提交时对台账额度行加锁，避免两个销售同时提交导致超额度；额度校验不通过会直接拒绝提交。

### 7.7 审批流程

```text
销售提交
  → 商务确认
  → 商务回填
  → 已确认
```

退回关系：

- 商务确认 → 退回销售；
- 商务回填 → 退回商务、退回销售。

## 8. SO管理

### 8.1 页面定位与入口

- 菜单：特商管理系统 → SO管理。
- 页面主对象是“商机池”，不是 SO申报单。
- 每次打开菜单，系统先刷新商机池，再显示列表；刷新失败会提示“商机库暂时不可用，当前显示的是上一次同步的数据”。
- SO申报单从商机池行的“发起SO申报”生成，不在页面上直接新增 SO单。

### 8.2 商机池列表

列表列：

| 列 | 说明 |
| --- | --- |
| 操作 | 发起SO申报/继续草稿，或查看SO申报 |
| 商机编号 | 销帮帮商机编号，池内唯一 |
| 商机名称 | 销帮帮商机名称 |
| 销售阶段 | L2 及以上阶段名称 |
| 是否报SO | 只展示，不作为进入池的条件 |
| 商机负责人 | 销帮帮负责人；无法映射时为空 |
| 合同金额 | 销帮帮合同金额 |
| 预计商机金额 | 销售预估金额，不是签约金额 |
| 预计签约、付款、交付时间 | 均为销帮帮计划口径 |
| 华为负责人 | 销帮帮华为侧负责人 |
| 产品 | 商机产品名称和数量 |
| SO状态 | 已发起 SO 的业务状态 |
| 商机仍存在 | 默认收起；销帮帮已删除但保留的池行显示否 |

搜索与筛选：

- 商机编号、商机名称、商机负责人、华为负责人；
- 我负责的、已发起SO、未发起SO、已发起下单、未发起下单、商机仍存在；
- 按销售阶段、商机负责人分组。

行操作：

- 点击行进入只读“商机详情”，可以查看商机编号、名称、销售阶段、是否报SO、商机负责人、商机是否仍存在、最近更新时间、合同金额、预计商机金额、三个预计日期、华为负责人，以及已发起 SO/下单及其状态、商机产品明细。
- 第一列按钮由服务端按当前页面生成：SO管理页显示“发起SO申报 / 继续SO申报（草稿）/ 查看SO申报（状态）”；下单申请页显示对应的下单按钮。
- 点击“发起”直接创建一张草稿并打开单据，不再弹确认框，也不占用商机；其他销售可以在同一商机上各自发起自己的草稿。
- 点击“继续”打开自己还没提交的那张草稿。
- 点击“查看”直接打开已占用商机的那张单据，不弹确认框。
- 商机已被别人提交占用、且自己没有草稿时，按钮位置显示“已被 XXX 认领（状态）”，不能发起。

商机池取数规则：

- 数据来自销帮帮商机，销售阶段 L1-线索不进入池，L2 及以上全部进入；
- “是否报SO”不作为过滤条件；
- 商机编号为空的行丢弃；同一编号保留最新一条；
- 产品名称为空或数量不大于 0 的行不展示；
- 商机在销帮帮被删除时：没有关联单据、也没有草稿的池行删除；已发起过单据、或还留着草稿的池行保留，并标记“商机仍存在 = 否”；
- 已提交单据的池行归属固定为提交人，后续销帮帮负责人变化不会把原提交人挤掉。

### 8.3 多草稿与提交认领规则

- 商机池上的“商机负责人”来自销帮帮；销帮帮没有负责人时为空。本系统认领商机后，池行会记录认领人，不会反向修改销帮帮的负责人。
- 只有特商销售组、管理员可以发起；审批组不能从商机池建单。
- 未分配负责人的商机属于公共池，谁先提交谁成为认领人。
- 已分配负责人的商机只对该负责人可见；未分配和已提交过的商机按记录规则处理。
- 点“发起”只生成一张草稿，不占商机：同一商机可以由不同销售各自持有一张自己的草稿，互不阻塞。草稿归发起人，商机负责人不会带到草稿上。
- 同一个人在同一商机上只保留一张草稿；重复点发起会提示“你在这个商机上已经有一张草稿”。
- 点“提交审批”时才真正认领商机：系统锁定商机池行，回写 SO申报单/下单申请单与认领人，再生成单号并启动流程。
- SO 和下单申请共用同一个商机认领：
  - 同一商机已经提交 SO（或已完成），其他人不能在该商机上提交下单申请；
  - 同一商机已经提交下单申请（或已完成），其他人不能在该商机上提交 SO；
  - 认领人本人可以先提交一种，再提交另一种（SO 报完接着下单）；
  - 其他人看到“已被 XXX 认领”。
- 两张草稿几乎同时提交时，先拿到池行锁的那张认领成功，另一张留在草稿并提示“该商机已被「XX」占用，占用人是 XXX”。
- 放弃草稿、撤回申请、作废都会释放商机占用并清空认领人，其他人可以重新发起；已被释放的商机在下一次刷新时用销帮帮的真实负责人回填。
- 已占用但当前用户无权限查看时，按钮显示“已被 XXX 认领”；非销售用户看到“仅销售可发起”。

### 8.4 SO申报详情

页面结构：

1. 顶部状态条：审批状态。
2. SO申报信息：
   - 系统带出且只读：SO申报单号、CRM名称、CRM编码、销售负责人、签约状态、签约金额、预计商机金额、签约时间、回款时间、交付时间、华为组织/负责人；
   - 销售维护：内部商机名称、内部商机编码、主板核数/数量、产品类型、SJ编码。
3. “金额信息”分组（仅 SO 敏感数据权限组可见）：
   - 成本、毛利、是否已下单；
   - 主板金额、其他金额、回填人、回填时间。
4. “欠账与历史订单信息”分组（仅 SO 敏感数据权限组可见）：
   - 欠账信息、历史订单信息。
5. “审批历史”页签：本单审批记录。

页面提示：

- CRM名称/编码、签约状态/金额、三个日期、华为组织/负责人由商机池发起时带出；要改应在销帮帮里改。
- 签约金额来自“合同金额”，多数商机为空；预计商机金额来自销售预估，两者不是同一口径。
- 点“提交审批”后才生成 SO 单号和审批任务；审批节点只审批，金额信息在“商务回填”节点填写。

### 8.5 页面操作

| 操作 | 出现条件 | 行为 |
| --- | --- | --- |
| 提交审批 | 草稿、被退回销售修改、未终止 | 校验必填项和流程绑定，生成单号，启动/恢复流程 |
| 通过 | 当前节点办理人，且不是回填节点、不是加签任务 | 审批通过 |
| 完成加签 | 当前用户是加签任务办理人 | 只完成自己的加签子任务 |
| 加签 | 风控负责人节点、当前办理人 | 打开加签向导 |
| 退回销售 | 当前节点允许 | 回到销售修改 |
| 退回销售组长/销售负责人/风控/商务执行 | 当前节点允许对应目标 | 回到指定前序节点 |
| 保存回填 | 商务回填节点办理人 | 保存金额信息，不推进流程 |
| 完成回填 | 商务回填节点办理人 | 校验已保存，结束流程，业务状态变为已完成 |
| 放弃草稿 | 申请人、未提交 | 单据作废，不启动流程，释放商机占用 |
| 撤回申请 | 申请人、审批中 | 终止流程，单据作废，释放商机占用 |
| 作废 | 当前节点办理人 | 终止流程，单据作废，释放商机占用 |

### 8.6 提交校验

SO申报点击“提交审批”前必须满足：

- 系统已经绑定 SO申报流程；未绑定时只提示去“配置 → 部署流程”部署，不生成单号；
- CRM编码不能为空；
- CRM名称不能为空；
- 内部商机名称不能为空；
- 内部商机编码不能为空；
- 主板核数/数量不能为空；
- 产品类型不能为空；
- SJ编码不能为空。

保存草稿不强制上述字段；提交时一次性列出所有缺项。

### 8.7 商务回填规则

- 只有“商务回填”节点的办理人可以编辑金额信息。
- 必须先在“保存回填”成功，才能“完成回填”。
- “是否已下单”是布尔开关：开表示是，关表示否；两种状态都合法，不再要求必须为“是”。
- 成本、毛利、主板金额、其他金额允许为空。
- 欠账信息、历史订单信息由商务维护。
- 完成回填后流程结束，SO 业务状态变为“已完成”，回填状态变为“已完成”。

### 8.8 审批流程

```text
销售提交
  → 销售组长审批（组长本人发起时跳过）
  → 销售负责人
  → 风控负责人
  → 商务执行人
  → 商务回填
  → 已完成
```

退回关系：

- 销售组长审批 → 退回销售；
- 销售负责人 → 退回销售组长、退回销售；
- 风控负责人 → 退回销售负责人、退回销售；
- 商务执行人 → 退回风控、退回销售；
- 商务回填 → 退回商务执行、退回销售。

加签：仅风控负责人节点开放。

## 9. 下单申请

### 9.1 页面定位与入口

- 菜单：特商管理系统 → 下单申请。
- 列表主对象同样是商机池；下单申请单从池行“发起下单申请”生成。
- 页面不提供直接新增下单申请单的入口；新单必须从商机池发起。

### 9.2 商机池列表

  - 第一列按钮是“发起下单申请 / 继续下单申请（草稿）/ 查看下单申请”；

### 9.3 下单申请详情

页面结构：

1. 顶部状态条：审批状态。
2. 基本信息：
   - 申请单号、CRM名称、CRM编码；
   - 内部商机名称、内部商机编码、SJ编码；
   - 产品类型（由明细汇总）、台套数（自动汇总）、销售负责人；
   - 当前节点、当前审核人、材料状态、回填状态、首次/最近提交时间。
3. “特商信息”分组：是否含特商、特商编码。
4. “中标信息”分组：是否已中标、SDT编码。
5. “主板明细”页签：主板型号、产品类型、台套数；同型号合并一行，不能重复。
6. “普通申请材料”页签：备货函、中标通知书等，至少一份。
7. “OEM验证表”页签：仅中标单显示；可后补；显示补交人和补交时间。
8. “订单回填”页签：备货价审单号、备货流程单号、1Y号、金额、回填人、回填时间。
9. “审批历史”页签：本单审批记录。

字段规则：

| 字段 | 维护方式 | 规则 |
| --- | --- | --- |
| 申请单号 | 系统 | 创建时生成 |
| CRM名称/编码 | 商机池带出，只读 | 避免手工造出重复单 |
| 内部商机名称/编码、SJ编码 | 销售手工填 | 提交前必填 |
| 是否含特商 | 销售选择 | 提交前必选 |
| 特商编码 | 销售手工填 | 含特商时必填；保存时去空格并转大写；不要求台账已建档 |
| 是否已中标 | 销售选择 | 提交前必选；商机阶段为 L3.5-赢取或 L4-双章时预填“是”，否则预填“否” |
| SDT编码 | 销售手工填 | 未中标时必填；选已中标时清空 |
| 主板型号 | 销售选择 | 只能选启用的型号；同一单不能重复 |
| 台套数 | 销售填写 | 正整数；由明细汇总 |
| 普通申请材料 | 销售上传 | 至少一份 |
| OEM表 | 销售上传 | 中标单可后补，不阻塞提交/回填 |
| 备货流程单号 | 回填审批节点填写 | 该节点通过前必须填写 |
| 备货价审单号 | 商务回填节点填写 | 可填，不是完成回填的必填项 |
| 1Y号 | 商务回填节点填写 | 完成回填前必填 |
| 金额 | 商务回填节点填写 | 完成回填前必填；显式为 0 也可接受，但需要先保存 |
| 回填状态/人/时间 | 系统 | 保存或完成回填时记录 |

商机产品转明细：

- 商机产品名称与本系统“主板型号”名称完全一致时才自动带入；
- 同一型号多行合并为一行；
- 匹配不上的产品不会硬塞成错误型号，需要销售手工补明细；
- 未匹配不阻止发起，销售在详情页补齐后才能提交。

### 9.4 页面操作

| 操作 | 出现条件 | 行为 |
| --- | --- | --- |
| 提交审批 | 草稿、被退回销售修改、未终止 | 表单先保存，再校验并启动/恢复流程；按钮在只读态工具栏“编辑”后 |
| 通过 | 当前节点办理人，且不是回填节点、不是加签任务 | 审批通过 |
| 完成加签 | 加签任务办理人 | 只完成加签子任务 |
| 加签 | 风控负责人节点 | 打开加签向导 |
| 保存回填 | 商务回填节点办理人 | 保存 1Y号、金额、价审单号等，不推进流程 |
| 完成回填 | 商务回填节点办理人 | 校验回填内容，结束办理，业务状态已完成 |
| 标记OEM表已补齐 | 中标单、已上传 OEM 表、材料仍待补 | 记录补交人和补交时间，不改型号与编码 |
| 退回销售/售前/组长/风控/商务执行（初审/回填后）/回填审批 | 当前节点允许对应目标 | 回到指定前序节点，流程保留 |
| 放弃草稿 | 申请人、未提交 | 单据作废，不启动流程，释放商机占用 |
| 撤回申请 | 申请人、审批中 | 终止流程，单据作废，释放商机占用 |
| 作废 | 当前节点办理人 | 终止流程，单据作废，释放商机占用 |

### 9.5 提交校验

点击“提交审批”前必须满足：

- 内部商机名称不能为空；
- 内部商机编码不能为空；
- SJ编码不能为空；
- 是否含特商必须选择；
- 含特商时特商编码必填；
- 主板明细至少一行；
- 每行必须选择主板型号；
- 每行台套数必须为正整数；
- 是否已中标必须选择；
- 未中标时 SDT 编码必填；
- 普通申请材料至少一份。

OEM 表、备货流程单号、备货价审单号、1Y号、金额属于审批/回填字段，不阻塞提交。

### 9.6 下单审批流程

```text
销售提交
  → 售前配置审核
  → 销售组长审批（组长本人发起时跳过）
  → 风控负责人
  → 商务执行人（初审）
  → 回填审批（填写备货流程单号）
  → 商务执行人（回填后）
  → 商务回填
  → 已完成
```

退回关系：

- 售前配置审核 → 退回销售；
- 销售组长审批 → 退回售前、退回销售；
- 风控负责人 → 退回销售组长、退回售前、退回销售；
- 商务执行人（初审）→ 退回风控、退回销售；
- 回填审批 → 退回商务执行（初审）、退回销售；
- 商务执行人（回填后）→ 退回回填审批、退回销售；
- 商务回填 → 退回商务执行（回填后）、退回销售。

加签：仅风控负责人节点开放。

### 9.7 回填与材料规则

回填审批节点：

- 只能填写“备货流程单号”；
- 点击“通过”前必须填写，否则系统拒绝；
- 后续节点只读展示该单号。

商务回填节点：

- 可填写备货价审单号、1Y号、金额；
- 1Y号必填；
- 金额必填；金额为 0 时也要显式填写并先“保存回填”，系统通过回填状态区分“没填”和“填了 0”；
- 价审单号非必填；
- 完成回填后业务状态变为“已完成”。

OEM：

- 只有中标单需要 OEM 项目真实性验证表；
- 未上传时材料状态为“待补OEM验证表”，不阻塞提交、审批和回填；
- 补齐后由销售点击“标记OEM表已补齐”，系统记录补交人和时间；
- 补交 OEM 不新建审批任务，也不重新开放型号和编码字段。

## 10. 我的申请 → 我的提交

### 10.1 页面定位

- 菜单：我的申请 → 我的提交。
- 用途：在一个列表里跟踪本人提交过的特商申请、延期、激活、SO申报、下单申请。
- 只读聚合页，不能在这里新建、编辑、删除或审批。
- 只收录已经提交过审批的单据（有首次提交时间）；草稿、放弃的草稿不进入。

### 10.2 列表字段

| 列 | 说明 |
| --- | --- |
| 申请单号 | 各单据自己的单号 |

| 项目/CRM名称 | 申请用 CRM 名称；延期/激活用项目名称；下单用内部商机名称 |
| 特商编码 | 有则显示 |
| 销售负责人 | 申请/下单/SO 取销售负责人；延期/激活取申请人 |
| 数量 | 申请/下单的台套数，激活的本次激活数；延期和 SO 为 0 |
| 审批状态 | 无审核、审核中、已审核、已驳回、已撤回 |

### 10.3 搜索与筛选

- 按申请单号、项目/CRM名称、特商编码、销售负责人搜索；
- 按单据类型筛选；
- 按审批中、已通过筛选；
- 按单据类型、审批状态分组。

### 10.4 数据范围与操作

- 销售组默认只看本人提交的单据；
- 商务、产品、商务审批、配置管理员可看全量，用于对账和流程跟踪；
- 点击“查看单据”回到原单据详情，后续操作仍按原单据的权限和节点规则执行。

## 11. 我的待办 → 待我处理 / 我已处理

### 11.1 待我处理

- 菜单：我的待办 → 待我处理。
- 显示未结束的特商流程任务，默认只显示分派给当前用户的任务。
- 列表列：单据号、当前节点、业务模型、指定处理人、候选组、发起人、到达时间、超期时间、打开单据。
- 行上的“打开单据”进入原业务单据；审批动作在业务单据上完成。
- “分派给我”的口径：任务的指定处理人是本人，或者候选组 / 候选人里恰好包含本人（按完整组名、完整登录名匹配，不做子串匹配，避免「特商销售组」误命中「特商销售组长组」）。
- 任务未认领时，节点办理组成员可以打开并办理，打开单据时完成认领；其他人打开只看单据，不会把任务认领成自己的。
- 加签子任务也会出现在这里，加签人打开后只能“完成加签”。

### 11.2 我已处理

- 菜单：我的待办 → 我已处理。
- 显示已经结束、且处理人是当前用户的任务。
- 列表列：单据号、节点、业务模型、处理人、处理结果、意见、到达时间、完成时间。
- 只能查看，不能重新办理。

### 11.3 审批任务规则

- 任务列表只负责展示和打开单据；不提供独立审批表单。
- 当前任务被其他人认领后，其他候选人不能再办理。
- 任务无人认领时，只有该节点办理组成员（或候选人）打开单据才会认领；不在办理组的人即使能看到任务，也不会被认领成办理人。
- 审批按钮的可见性由业务单据上的当前节点、当前办理人和角色组共同决定；服务端在提交审批动作时再校一次办理组，不依赖按钮显隐。
- “退回”后原流程实例保留，目标节点生成新任务；“重新提交”完成销售修改任务，不新建流程实例。
- 撤回、放弃、作废会把本地未结束任务一并关闭，避免待办里留下打不开的僵尸任务。
- 审批动作不能只有按钮入口：dcg 的 `do_approve` / `do_reject` 是公开方法，RPC 可直接调用，业务单据上这两个入口同样要过节点办理组校验；`action_approve` / `action_reject` 上的加签拦截、返工节点拦截也必须在 `do_*` 上重复一次。
- `bpmn.task` 对全部内部用户可读写建删、且没有记录规则（dcg 现状），因此“先把任务转给自己、再调 do_approve”是一条必须堵住的越权路径：bpmn.task 侧只允许候选人自认领、当前办理人转派、系统管理员操作，且只作用于特商 12~16 五类任务，其他流程不受影响。
- 新加的流程动作一律按“服务端先校验、按钮只管显隐”落地；视图 attrs 挡不住 RPC 和旧页面缓存。

## 12. 日志 → 审批日志

- 菜单：日志 → 审批日志。
- 显示五类特商流程的审批历史：特商申请、延期、激活、下单申请、SO申报。
- 列表列：节点、办理人、结果、意见、开始时间、结束时间、流程实例。
- 支持按节点、办理人、流程实例搜索。
- 支持筛选“回退记录”“拒绝/作废”，可按结果分组。
- 审批日志是只读留痕，不提供修改和删除。
- 业务字段的前后值由系统审计日志负责，不在本页面展示。

## 13. 配置

### 13.1 主板型号

- 菜单：配置 → 主板型号。
- 页面为可编辑列表和详情表单。
- 字段：
  - 产品类型：鲲鹏、昇腾；
  - 型号名称；
  - 启用；
  - 备注。
- 规则：
  - 同一产品类型下型号名称不能重复；
  - 已被申请明细或台账明细引用的型号只能停用，不能删除；
  - 停用型号不会出现在新申请/新下单的型号下拉中；
  - 产品类型不是独立字典页面，维护在型号行上。

### 13.2 审批用户组

- 菜单：配置 → 审批用户组。
- 页面只列出“特商管理系统-菜单权限管理”分类下的用户组。
- 可查看组名、组成员和组之间的继承关系；实际编辑受 Odoo 基础权限控制，通常需要系统管理或 ERP 管理权限；只有特商配置菜单权限的账号可能只能查看。
- 业务要求：
  - 审批组名称必须与部署到 Flowable 的流程节点候选组名称一致；
  - 数据组（销售组、商务组、产品组）负责数据范围，不直接作为审批节点候选组；
  - 修改组名后必须重新部署对应 BPMN，否则已部署流程仍按旧组名派单；
  - 不建议通过扩大数据组写权限来替代审批节点权限。

### 13.3 部署流程

- 菜单：配置 → 部署流程。
- 弹窗字段：
  - 流程：特商申请、特商延期、特商激活、下单申请、SO申报；
  - 本地当前版本；
  - BPMN 文件：可上传，也可留空读取模块内置文件；
  - 租户 ID：通常留空；
  - 部署后说明。
- 操作：部署、取消。
- 规则：
  - 文件中的流程标识必须与所选流程 key 一致，不一致直接拒绝，防止误建新流程；
  - 部署成功后生成新版本，旧版本保留，在途流程仍跑旧版本；
  - 部署成功后系统自动把业务模型绑定到新版本；
  - 只允许 .bpmn20.xml 或 .bpmn 文件；
  - 同一事务内防止连点重复部署；
  - 流程文件未绑定到业务模型时，SO 等页面提交会提示先部署/绑定，不会生成单号或启动流程。

## 14. 端到端流程与状态汇总

### 14.1 特商申请主线

```text
新增申请草稿
  → 提交审批（待生效）
  → 商务经理审批
  → 产品经理审批
  → 商务回填（特商编码、开始/结束时间、价格、折扣）
  → 完成回填
  → 已生效 + 生成台账
```

异常分支：

- 草稿阶段放弃 → 已作废，不生成台账；
- 审批中撤回 → 已作废，流程终止；
- 审批人作废 → 已作废，流程终止；
- 退回销售/商务/产品 → 流程保留，修改后重新提交；
- 商务回填校验不通过 → 流程停在回填节点，补全后继续。

### 14.2 台账主线

```text
特商申请已生效
  → 台账有效
  → 临近/已经到期 → 发起延期 → 商务确认 → 商务回填 → 到期日更新、延期次数 +1
  → 有效期内的额度 → 发起激活 → 商务确认 → 商务回填 → 占用转为已激活
```

台账状态只有“有效”和“已过期”，由到期日与当天比较自动计算；过期后台账仍可查看，但发起激活会被拒绝，需先延期。

### 14.3 SO/下单主线

```text
打开商机池
  → 刷新销帮帮商机
  → 选择商机，点击发起
  → 生成自己的草稿（不占商机，可多人各持一张）
  → 补齐本系统字段
  → 提交审批（此时锁池行、回写单据与认领人、生成单号）
  → 各审批节点
  → 回填节点
  → 完成
```

同一商机的占用关系：

- 草稿不占商机，多张草稿可以共存；
- 第一个提交审批的人占用商机，其他人看到“已被 XXX 认领”；
- 占用人可以继续提交另一种单据（SO → 下单）；
- 放弃草稿、撤回、作废后释放占用，其他人可以重新发起；
- 释放后再提交，新的提交人成为新认领人。

### 14.4 状态汇总

| 场景 | 审批状态 | 业务状态 | 是否可继续操作 |
| --- | --- | --- | --- |
| 申请草稿 | 无审核 | 草稿 | 可编辑、可提交、可放弃 |
| 申请审批中 | 审核中 | 待生效 | 审批人处理；申请人可撤回 |
| 申请已通过 | 已审核 | 已生效 | 只读；延期/激活从台账发起 |
| 申请被退回 | 审核中 | 待生效 | 销售修改后重新提交 |
| 申请撤回/放弃/作废 | 已撤回/已驳回 | 已作废 | 不可重提 |
| 延期/激活草稿 | 无审核 | 草稿 | 可编辑、可提交、可放弃 |
| 延期/激活审批中 | 审核中 | 审批中 | 审批人处理；申请人可撤回 |
| 延期/激活已完成 | 已审核 | 已确认 | 只读 |
| 延期/激活取消 | 已撤回/已驳回 | 已取消 | 不可重提 |
| SO/下单草稿 | 无审核 | 草稿 | 可编辑、可提交、可放弃 |
| SO/下单审批中 | 审核中 | 办理中 | 审批人处理；申请人可撤回 |
| SO/下单完成 | 已审核 | 已完成 | 只读 |
| SO/下单作废 | 已撤回/已驳回 | 已作废 | 不可重提；商机可重新发起 |

| 流程 | 节点 | 办理组/办理人 |
| --- | --- | --- |
| 特商申请 | 商务经理审批、商务回填 | 特商商务审批组 |
| 特商申请 | 产品经理审批 | 特商产品审批组 |
| 特商申请 | 销售修改 | 申请人本人 |
| 延期/激活 | 商务确认、商务回填 | 特商商务审批组 |
| 延期/激活 | 销售修改 | 申请人本人 |
| SO申报 | 销售组长审批 | 特商销售组长组 |
| SO申报 | 销售负责人 | 特商SO销售负责人组 |
| SO申报 | 风控负责人 | 特商风控审批组；可加签 |
| SO申报 | 商务执行人、商务回填 | 特商商务审批组 |
| SO申报 | 销售修改 | 申请人本人 |
| 下单申请 | 售前配置审核 | 特商售前配置审核组 |

节点名称必须与已部署 BPMN 中的 userTask 名称一致；审批按钮按节点名称匹配办理组，改名后需要同步流程并重新部署。

## 15. 验收场景

### 15.1 特商申请

1. 销售从“特商申请”点“新增申请”，填写 CRM、SJ、华为负责人、明细和附件，保存草稿成功。
2. 提交时缺少附件或必填字段，系统一次性列出全部缺项，不启动流程。
3. 补齐后提交，单据进入“待生效”，待办中出现商务经理审批任务。
4. 商务经理通过、产品经理通过后进入商务回填；销售看不到价格和折扣。
5. 商务填写特商编码、开始/结束时间、价格、折扣，可先暂存；直接点“通过”时系统校验并记录回填信息。
6. 点“通过”完成回填后申请变为“已生效”，生成台账，台账编码、负责人、有效期、额度与申请一致。

### 15.2 特商延期

1. 延期页默认显示当月到期台账，行点击不进入表单，操作列显示“发起延期”。
2. 非负责人/非共享人看到按钮置灰，服务端也拒绝发起。
3. 已有草稿时再次点击“发起延期”，直接打开原草稿，不新建第二张。
4. 期望日期早于或等于原到期日时不能提交；同一台账已有未完成延期时不能重复发起。
5. 商务确认后进入商务回填；填写实际确认到期日并完成回填后，台账到期日、延期次数、最近延期时间更新，申请单的结束时间同步。

### 15.3 特商激活

1. 激活页选择台账行，新建激活申请时自动铺开所有型号明细。
2. 未勾选任何型号、数量为 0、数量超过可用额度时不能提交。
3. 提交成功后待确认占用增加，已激活不变。
4. 商务确认不改变额度；完成回填后占用转为已激活。
5. 退回销售、放弃、撤回、作废后占用释放；重新提交重新校验额度。

### 15.4 SO管理

1. 打开 SO管理，系统刷新商机池；刷新失败时提示并保留上次数据。
2. 未分配商机所有销售可见；点击发起直接创建草稿并打开，不弹确认框、不占商机；两个销售可以在同一商机上各建一张草稿。
3. 第一个提交审批的人占用商机；其他人看到“已被 XXX 认领”，不能提交，也不能从下单申请页绕过。
4. 占用人可以继续在同一商机上发起下单申请。
5. 放弃 SO 草稿后商机释放，其他人可以发起；新提交人成为新认领人。
6. SO 提交时缺少内部商机、主板核数、产品类型、SJ编码等，系统一次性报错；补齐后占用商机、生成 SO 单号并进入流程。
7. 风控节点可加签；加签人能在待我处理看到任务，完成加签后原办理人才能继续。
8. 商务回填节点选择“是否已下单 = 否”并保存后，可以完成回填。

### 15.5 下单申请

1. 打开下单申请页，商机池显示“发起下单申请”；点击后直接生成草稿，不弹确认框、不占商机。
2. 商机产品名称能匹配主板型号时自动带入明细；匹配不上时不强行带入，销售手工补齐。
3. 提交时校验内部商机、SJ编码、是否含特商、特商编码、明细、是否中标、SDT、普通申请材料。
4. 中标单未上传 OEM 表时材料状态为“待补OEM验证表”，但可以提交、审批和回填；补齐后可以标记已补齐。
5. 回填审批节点不填备货流程单号不能通过。
6. 商务回填节点填写 1Y号、金额，保存后完成回填；金额 0 也必须显式保存。
7. 退回、撤回、作废的状态和待办清理符合第 4 章规则。

### 15.6 我的申请、待办、日志

1. 提交过的五类单据都出现在“我的提交”，草稿不出现。
2. 销售只看到本人单据；商务/产品/审批/配置能看到全量。
3. “待我处理”默认只显示分派给本人的任务，打开任务进入业务单据办理。
4. 完成审批后任务进入“我已处理”，审批日志能查到对应节点和结果。
5. 加签任务出现在待我处理，只能完成加签，不能作废整张单。

### 15.7 权限与配置

1. 没有销售组权限的审批人员只能审批，不能从商机池发起新单。
2. 销售看不到特商申请价格、折扣和 SO 敏感金额字段。
3. 非当前节点办理人即使通过接口调用，也无法通过/退回/作废。
4. 主板型号被引用后只能停用不能删除；停用型号不再出现在下拉中。
5. 部署流程时文件流程标识与选择项不一致会被拒绝；部署成功后新版本生效并自动绑定。
6. 修改审批组名称后重新部署流程，否则旧流程实例仍按旧组名派单。

## 16. 边界与已知限制

以下内容是当前实现边界，需要在业务验收和后续迭代中明确：

1. 测试机管理不在本文范围。
2. 特商延期、激活没有独立的菜单列表页；它们从台账页的“发起延期/发起激活”进入，历史单据通过“我的提交”或台账日志查看。
3. 延期页、激活页的列表行点击被禁用，必须使用操作列按钮；这是为了避免用户误入表单，不是权限问题。
4. 特商申请、SO申报、下单申请的原生“创建”按钮均关闭；特商申请用列表“新增申请”，SO/下单必须从商机池发起。
5. SO 草稿阶段单号为空，提交成功后才生成；因此草稿在列表/我的提交里可能没有 SO 单号。
6. 下单申请的特商编码是文本，不要求台账已存在；台账按编码反查关联下单，编码填错时不会自动纠正。
7. 下单申请从商机带明细时按产品名称精确匹配主板型号，匹配不上不会自动创建型号，也不会强行填入错误型号。
8. 下单金额 0 与未填在数据库里都是 0，系统通过“保存回填”状态区分；因此金额 0 必须显式保存后才能完成回填。
9. SO 的“是否已下单”是布尔开关，关闭即表示“否”，页面没有单独的“未选择”状态；当前规则允许“是”和“否”两种结果。
10. 延期完成回填只校验“实际确认到期日必填”和“台账快照一致”，没有额外强制实际日期晚于原到期日；业务上由商务确认合理性。
11. 特商台账对销售组当前是全量可读，但只有负责人、共享人、管理员可以发起延期/激活；如果后续要求销售只能看本人台账，需要调整记录规则。
12. 审批日志是流程历史，不是业务字段变更审计；字段前后值由系统审计日志负责。
13. 审批用户组页面的编辑能力依赖 Odoo 基础权限（系统/ERP 管理），特商配置管理员本身不自动获得修改系统用户组的权限；现场如果只能查看，需要用具备基础权限的账号维护。

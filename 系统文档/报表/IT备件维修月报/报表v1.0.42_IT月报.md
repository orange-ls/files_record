##### 二、是否命中需求

需求：“是否备件命中”原逻辑是直接赋值为空，现在增加赋值逻辑：

1、若“crm服务市”为空，直接赋值为“是”

2、备件测算查询sql

```sql
SELECT DISTINCT proj_number,delivery_location,stock_location FROM bom_total_table

SELECT DISTINCT proj_name,delivery_location,stock_location FROM bom_total_table
```

字段说明：proj_number：CRM立项编号、proj_name：项目名称、delivery_location：交付地点、stock_location：库存地点。
查询结果存在一个crm立项编号有多行，所以要按CRM立项编号、项目名称进行汇总，例如{crm立项编号:[(交付地点,库存地点),...]}

3、按CRM立项编号匹配2中的结果，如果不存在再用项目名称匹配。如果两种都匹配不上，“是否备件命中”设置为“否”并进入“特殊情况筛选”逻辑，“特殊情况筛选”的具体逻辑后面介绍。

4、3中匹配的结果和计算维修收发货表进行核对："crm服务市"模糊匹配"交付地点" and "备件出库地"模糊匹配“库存地点”。两个都匹配上，“是否备件命中”设置为“是”，否则为“否”。“是否备件命中”设置为“否”时，进入“特殊情况筛选”逻辑。
模糊匹配举例："crm服务市"=“佛山市”，"交付地点"=“佛山”；"备件出库地"=“广州”，“库存地点”=“广州”，此时算匹配上。"crm服务市"=“广州”，"交付地点"=“佛山”；"备件出库地"=“广州”，“库存地点”=“广州”，此时没匹配上。

5、“是否备件命中”设置为“是”时，“命中备注”填充为：命中。

6、“特殊情况筛选”逻辑（只有“是否备件命中”设置为“否”才进入）：

6.1：查询溯源系统数据

数据准备：

```sql
SELECT crm_no,city
FROM sn_service_complete_info
WHERE crm_no is not null or city is not null
GROUP BY crm_no,city

SELECT proj_name,city
FROM sn_service_complete_info
WHERE proj_name is not null or city is not null
GROUP BY proj_name,city

SELECT complete_sn,min(deliver_time) deliver_time
FROM sn_service_complete_info
WHERE complete_sn in (***,***...) -- 查询列表为计算维修收发货表中的整机SN，分批查询
GROUP BY complete_sn
```

crm_no：CRM立项编号、proj_name：项目名称、city：所在城市、complete_sn：整机SN、deliver_time：产品交付时间。

同一个CRM立项编号、项目名称存在多个“所在城市”，需要汇总。例：{CRM立项编号: [城市1，城市2...]}。



判断逻辑：

if：如果计算维修收发货表中的“CRM立项编号”和“项目名称”都不在sql结果中：“实际是否命中”设置为“是”，“命中备注”填充为：“CRM立项编号和项目名称在溯源系统都未查到”。

elif：按“整机SN”匹配查询结果，如果"产品交付时间"和当前日期在14天内：“实际是否命中”设置为“是”，“命中备注”填充为：“整机的产品交付时间在14天内”。如果超过14天或查不到“整机SN”：进入下一个判断。

elif：使用“CRM立项编号”获取溯源系统的“所在城市”，如果所有“所在城市”和“crm服务市”都不能模糊匹配上：“实际是否命中”设置为“是”，“命中备注”填充为：“报修的客户城市和溯源系统所在城市不一致”。否则进入下一个判断。

else：记录当前的“CRM工单号”、“CRM立项编号”、“项目名称”、“报修物料代码”、“报修时间”。例：{(“CRM立项编号”,“报修物料代码”):[{“CRM工单号”、“CRM立项编号”、“项目名称”、“报修物料代码”、“报修时间”},...]}。

并设置“实际是否命中”为“”，“命中备注”填充为：“”。

6.2、全部数据都执行完后，判断6.1的else中记录的数据：

如果(“CRM立项编号”,“报修物料代码”)的值长度大于1，累计““报修时间”在”最晚““报修时间””前2天时间范围内的的所有数据条数，并计算“不良率”=累计条数/总销量。

如果“不良率”>"标准不良率"：“实际是否命中”设置为“是”，“命中备注”填充为：“48h内同一个CRM立项编号报修同一个物料多个,且不良率超过该物料标准不良率”。

如果“不良率”>"标准不良率"：“实际是否命中”设置为“否”，“命中备注”填充为：“真实未命中”。

总销量：

```sql
SELECT proj_number,material_mode,sum(sum_count) sum_count
FROM bom_total_table
GROUP BY proj_number,material_mode
```

proj_number：CRM立项编号、material_mode：物料号、sum_count：总数量。

标准不良率：

```SQL
SELECT sap_no,max(theoretical_defect_rate) rate FROM reject_ratio GROUP BY sap_no
```

sap_no：物料号，rate：标准不良率

如果长度等于1的，设置“实际是否命中”为“否”，“命中备注”填充为：“真实未命中”

##### 一、是否超时需求

需求：在计算维修收发货报表中，增加字段：“备件需求送达时间”、“crm服务市”、“是否备件命中”，并修改原字段”是否超时“的逻辑。

1、使用sql查询：

```sql
SELECT
		cao.name,
		cao.create_time,
		cao.is_adjust_appointment_time__c,
		cao.actual_time__c,
		cdo.field_service_product_category__c AS field_rV3o1__c,
		cao.field_city__c
FROM
		cases_obj cao
		LEFT JOIN (
			SELECT 
					cases_id,
					MAX(field_service_product_category__c) AS field_service_product_category__c
			FROM cases_device_obj
			GROUP BY cases_id
		) cdo ON cao.id = cdo.cases_id
WHERE
		cao.name IN ('****','****','****',...)
```

cao.name：CRM工单号、cao.create_time：创建时间、cao.is_adjust_appointment_timec：是否调整预约上门时间、cao.actual_timec：实际预约上门时间、field_rV3o1__c：服务产品类别、cao.field_cityc：crm服务市

2、“原预约上门时间”逻辑：”创建时间“+”服务产品类别“对应的期限。

”创建时间“的格式是：2026-04-01 15:10:20
”服务产品类别“的格式是：4U5年金牌+，5年介质保留。或者是：2U3年标准+, 基础硬件安装。
”服务产品类别“对应的期限：白金：后延2h、金牌/黄金：后延4h、不带前面几个名称的均为标准ND：次日18点

如果”服务产品类别“为空，默认

3、“备件需求送达时间”取值逻辑：”是否调整预约上门时间“为否时，直接取步骤2中的“原预约上门时间”。”是否调整预约上门时间“为是，且“实际预约上门时间”有值时，比较步骤2中的“原预约上门时间”和“实际预约上门时间”，取时间更晚的那个。

4、在导入方法中，加入“备件需求送达时间”、“crm服务市”、“是否备件命中”、”是否超时“的赋值入库。

按“CRM工单号”来匹配：

​	1、“备件需求送达时间”取步骤3的值。

​	2、“crm服务市”取步骤1中的“crm服务市”。

​	3、“是否备件命中”：固定为空字符串
​	4、”是否超时“：导入表中的“备件签收时间”晚于“备件需求送达时间”：是；导入表中的“备件签收时间”早于“备件需求送达时间”：否。

##### 保外维修：

保外维修模板-逻辑.xlsx按照这个表格中的内容，在 report_menu.xml"基础数据报表"菜单最后增加子菜单“保外维修”。
要求和逻辑说明如下：
1、表格第一行是字段名。第二行是数据逻辑。3~6行时示例数据。
2、以excel表格导入作为主要的更新方法，所有数据不支持页面编辑，有创建、导出功能。导入时表格已有内容优先级最高，为空的如果有抓取逻辑就抓取，没有就填充为空。
3、唯一键：CRM工单号 + 换件单号 + 返厂单号 + 故障件SN。例如：第3、4行的唯一键相同，后面行(4行)的数据覆盖前面行(3行)。四个唯一键字段全为空的行跳过不导入；只要其中任一字段有值，即正常导入处理。唯一键字段为空时入库统一存为 NULL（空串/纯空白先归一），避免 '' 与 NULL 两种“空”并存导致重复导入。
4、“物料捆绑料号”(R列)按“故障件物料号”(G列) = material_inventory.py.material_number 抓取bundling_number。
5、"捆绑料号平均价"(S列) 按”物料捆绑料号“取material_inventory.py 对应bundling_number所有moving_average_price的平均值。
6、"捆绑料号最高价"(V列) 按”物料捆绑料号“取material_inventory.py 对应bundling_number所有moving_average_price中的最大值。
7、"是否送修"(X列) ”维修站收费价格（含税总报价）“ > "捆绑料号平均价*0.3" : 待议价或弃修;”维修站收费价格（含税总报价）“ <= "捆绑料号平均价*0.3" : 确认维修。
8、”重复故障计数“(Z列) 导入数据中，第一次出现的”故障件SN“记为1，若出现多次，后续每出现一次，那条数据的”重复故障计数“的值加1。例如：第5、6行的”故障件SN“相同，第5行的”重复故障计数“为1，第6行的”重复故障计数“应该为2。故障件SN 为空的行不参与自动计数，该列留空入库。
9、“序号”列由系统生成，导入时不读取文件中的序号（填什么都忽略）。新建记录（页面新建或导入新增）时取库中已有最大序号 +1，从 1 开始连续递增；覆盖更新已有记录不改变其序号。
10、列表中展示“序号”，“导出”文件包含“序号”列，值为系统生成后的序号。



##### 保外维修概览

从'warranty.repair'中获取数据，按"返修申请日期"的年份 筛选(默认全选)



**列表数据：**

表头：“保外指标项”、“送修数量”、“修复率”、“维修收费合计”、“平均维修单价”

“保外指标项”：获取“备件大类”字段的数据，并进行汇总

“送修数量”：汇总当前“备件大类”的条数
“修复率”：“是否修复”为“已修复”记为1，“未修复”记为0。汇总后的值 / “送修数量”

“平均维修单价”：“维修收费合计” / “送修数量”



最后增加一行汇总行，“修复率”和“平均维修单价”使用汇总行汇总后的数据就行计算获得。

##### 维护说明（一次性手工执行，不写进模块代码）

存量数据的清理与旧约束的删除由人工在数据库客户端执行一次，代码不做自动删除，也不放进模块的 data/post_init，避免每次升级重跑。

```sql
-- 方案A（推荐，库内均为测试/可重导数据）：清空全表，序号从 1 重新开始
DELETE FROM warranty_repair;

-- 方案B：只清理序号为空/非数字的历史行，其余保留
DELETE FROM warranty_repair WHERE sequence IS NULL OR sequence !~ '^[0-9]+$';

-- 唯一键改为四字段（CRM工单号+换件单号+返厂单号+故障件SN）后，
-- 模块升级不会自动删除旧的两字段唯一约束（Odoo 按约束名匹配，改名即脱管），需手工执行一次：
ALTER TABLE warranty_repair DROP CONSTRAINT IF EXISTS warranty_repair_exchange_order_faulty_sn_unique;

-- 清理唯一键匹配失效期间误插入的重复行（同四字段键保留最新一条，与"后行覆盖前行"口径一致）：
DELETE FROM warranty_repair a
USING warranty_repair b
WHERE a.id < b.id
  AND COALESCE(a.crm_order_number, '') = COALESCE(b.crm_order_number, '')
  AND COALESCE(a.exchange_order_number, '') = COALESCE(b.exchange_order_number, '')
  AND COALESCE(a.return_order_number, '') = COALESCE(b.return_order_number, '')
  AND COALESCE(a.faulty_sn, '') = COALESCE(b.faulty_sn, '');

-- 统一历史空串/纯空白为 NULL（Odoo 的 Char 会把 '' 原样入库，''与NULL并存导致键匹配与约束都判不等）：
UPDATE warranty_repair SET crm_order_number = NULL WHERE btrim(crm_order_number) = '';
UPDATE warranty_repair SET exchange_order_number = NULL WHERE btrim(exchange_order_number) = '';
UPDATE warranty_repair SET return_order_number = NULL WHERE btrim(return_order_number) = '';
UPDATE warranty_repair SET faulty_sn = NULL WHERE btrim(faulty_sn) = '';
```

补充说明：
- 四个唯一键字段中任一为空时，PostgreSQL 的 UNIQUE 约束不去重（NULL 之间互不相等），导入的覆盖去重由代码内四元组精确匹配兜底；导入入库前会把键字段的空串/纯空白统一折成 NULL。
- 若存量数据违反新的四字段唯一性，模块升级日志会报约束创建失败（不中断升级），按上面任一方案清理后重跑 `-u xc_report` 即可补建。
- 修改 models/*.py 后必须重启 Odoo 服务才生效（非 --dev 模式不热加载 Python 代码）；未重启时重复导入会出现键字段含空值的行被反复新增的现象（空 Char 读出为 False 与文件侧 None 匹配不中）。

# 产品分类管理「别名」实施计划

> 模块：`xc_material_manage`　模型：`xc.plm.product.category`　
> 范围：仅「信创物料管理系统」内部，本期不做 `xc_quotwise` 侧接口
> 状态：代码已完成（2026-10-22），待部署测试机验证

## 1. 需求

产品分类管理（`xc.plm.product.category`，每行一条「Ⅰ→Ⅳ级」完整路径）增加「别名」，用于记录该分类的其他叫法。一条分类可有多个别名，**一个别名只能属于一条分类**。

## 2. 设计口径

| 项 | 结论 | 说明 |
|---|---|---|
| 挂载粒度 | 挂在分类行上，归语义为「该行最深非空级」 | 行的 Ⅲ/Ⅳ 级为空时，别名自动对应到 Ⅱ/Ⅲ 级，不需要额外建节点表 |
| 关系 | **One2many**（别名 → 分类 为多对一） | 一个别名只能挂一条分类，唯一约束保证 |
| 唯一性 | 分类内唯一 + **别名全局唯一** | 全局唯一：同一别名不得出现在两条分类下 |
| 大小写 | 大小写敏感 | 与现有分类数据一致（库中「2.5 NVME SSD」与「2.5 NVMe SSD」并存是真实业务） |
| 归一化 | create/write 统一 `strip()`，空串不落库 | 防止「PSU」与「PSU 」绕过唯一约束 |
| 删除 | 别名**物理删除**；分类删除时级联删除 | 别名是随分类走的配置数据，无业务历史；逻辑删除会与全局唯一约束冲突（停用记录会挡住同名重建），故此处偏离「默认逻辑删除」约定 |
| 停用 | 分类停用（`active=False`）时别名保留 | 重新启用后别名仍在 |
| 跨模块 | 本期不提供 | 不向 `xc_quotwise` 暴露任何方法，后续需要时再单独提需求 |

## 3. 数据模型

### 3.1 新增模型 `xc.plm.category.alias`（产品分类别名，与分类模型同文件）

> 该模型类与 `xc.plm.product.category` 定义在同一个文件 `models/plm/xc_plm_product_category.py`
> 内，不单独建模型文件：两者是一对多的主从关系、生命周期完全绑定，放一起便于对照维护。

| 字段 | 类型 | 属性 |
|---|---|---|
| `name` | Char | `string='别名'`、`required=True`、`index=True` |
| `category_id` | Many2one(`xc.plm.product.category`) | `string='所属分类'`、`required=True`、`ondelete='cascade'`、`index=True` |
| `category_path_label` | Char | 非存储 compute，拼出「Ⅰ/Ⅱ/Ⅲ/Ⅳ」非空级，供弹窗标题提示当前分类 |

```python
_sql_constraints = [
    ('alias_name_uniq', 'UNIQUE(name)', '该别名已存在'),
]
```

- `_order = 'category_id, id'`
- 不设 `active`（理由见 §2 删除一行）
- `create`/`write` 对 `name` 做 `strip()`，空值抛 `UserError('别名不能为空')`

### 3.2 分类模型新增字段

| 字段 | 定义 | 用途 |
|---|---|---|
| `alias_ids` | `One2many('xc.plm.category.alias', 'category_id', string='别名')` | 存储与维护 |
| `alias_names` | `Char`，非存储 compute | 列表只读展示、导出取数 |

`alias_names` 拼接规则：按 `id` 升序取全部别名，用 ` / ` 连接；超过 3 个时显示「前 3 个 + 等 N 个」。

## 4. 为什么是 One2many，不是 Many2many

初版方案曾用 `Many2many` + `many2many_tags`，目的是拿到列表内「标签列直接编辑」的交互，但**建模不正确**，已否决：

| 对比项 | One2many（采用） | Many2many（否决） |
|---|---|---|
| 语义 | 一个别名必属一条分类，与业务完全一致 | 关系表允许多分类共享同一别名，与业务不符 |
| 约束落地 | `UNIQUE(name)` 直接落在别名表 | 需在关系表上另建 `UNIQUE(alias_id)` 才能强行压成一对一，属变通 |
| 表数量 | 1 张 | 2 张（别名表 + 关系表） |
| 删除 | `ondelete='cascade'` 自动清理 | 解除关联后残留孤儿别名，需额外写清理 SQL |
| 列表内 tags 编辑 | 不支持 | 支持 |

关于「列内 tags 编辑」为什么随 m2m 一起去掉：Odoo 14 的 `many2many_tags` 控件在 `addons/web/static/src/js/fields/relational_fields.js` 中声明 `supportedFieldTypes: ['many2many']`，且写值用 `ADD_M2M` / `FORGET` 命令，One2many 无法套用，也没有等价的内置控件。

## 5. 页面与交互

### 5.1 分类列表（`xc_plm_product_category_tree_view`）

列顺序（操作列固定在**最后一列**）：

| 位置 | 列 | 控件 | 说明 |
|---|---|---|---|
| Ⅳ级之后 | 别名 | `alias_names`，`readonly="1"` | 展示为 `PSU / 电源模块 / 图形卡`，超出折叠 |
| 最后 | 操作 | `button_view`（`fields.Html('操作')`）+ `widget="xc_plm_category_alias"` | 单元格内是「修改别名」链接按钮，HTML 由 `search_read` 注入 |

**操作列沿用 PLM 物料列表的既有范式**（`xc_plm_material.py` 的 `button_view`）：

| 环节 | 实现 |
|---|---|
| 列名与单元格 | 模型加 `button_view = fields.Html('操作', compute='_button_html_view', sanitize=False)`，compute 空实现 |
| 按钮 HTML | 重写 `search_read()`，仅当 `fields` 为空或含 `button_view` 时逐行注入 `<span class="fa fa-tags o_list_category_alias goto-link">修改别名</span>` |
| 点击分发 | 新增 widget `xc_plm_category_alias`（`FieldMonetary` 子类，其 `_renderReadonly` 走 `$el.html()` 才能原样渲染注入的 HTML），点击后 `trigger_up('button_clicked', {attrs:{name:'action_open_aliases', type:'object'}, record})` 转交列表原生对象按钮流程 |
| 弹窗关闭后刷新 | 复用框架的 `on_closed → controller.reload()`，无需自己写刷新 |
| 未保存新行 | 没有 `res_id`，widget 拦下并提示「请先保存当前行，再修改别名」 |

- Ⅰ~Ⅳ级列对已有行的 `readonly` 属性**原样不动**
- 该 JS 通过 `views/templates.xml` 的 `web.assets_backend` 继承加载，**manifest 无需改动**

### 5.2 别名维护弹窗

服务端方法返回 `ir.actions.act_window`，无需前端代码：

```python
def action_open_aliases(self):
    self.ensure_one()
    path = ' / '.join(v for v in (self.product_category1, self.product_category2,
                                  self.product_category3, self.product_category4) if v)
    return {
        'type': 'ir.actions.act_window',
        'name': '别名 — %s' % path,
        'res_model': 'xc.plm.category.alias',
        'view_mode': 'tree',
        'views': [(self.env.ref('xc_material_manage.xc_plm_category_alias_tree_view').id, 'tree')],
        'domain': [('category_id', '=', self.id)],
        'context': {'default_category_id': self.id},
        'target': 'new',
    }
```

弹窗内为 `editable="bottom"` 的别名列表，可一次增删改多条，关闭即返回分类列表。

**关闭后列表刷新已验证，无需任何前端代码**：`BasicController._executeButtonAction` 传入
`on_closed: () => this.reload()`（`addons/web/static/src/js/views/basic/basic_controller.js:437`），
`ActionManagerActWindow._onExecuteAction` 将其转成 `options.on_close` 交给 `doAction`
（`action_manager_act_window.js:686`），弹窗 `closed` 时回放该回调（`action_manager.js:389`）。
因此点保存/取消关闭弹窗后分类列表会自动重载，别名列随之更新。

**弹窗按钮精简**（`target='new'` 的列表弹窗原生会渲染两套按钮）：

| 位置 | 原生行为 | 处理 |
|---|---|---|
| 底部 footer | 「创建」+「导出」 | 别名 tree 挂 `js_class="xc_plm_category_button"`，`CategoryListController.renderButtons` 命中 `modal-footer` 时跳过渲染并隐藏 footer |
| 顶部 | 「创建」+「导出」 | 「创建」保留（弹窗内新增别名行靠它）；「导出」由该 js_class 的 `activeActions.export_xlsx = false` 去掉 |

跳过而不是渲染后再清空的原因：`renderButtons` 每次调用都会重建 `this.$buttons`，若让
footer 那次照常执行，`this.$buttons` 会被替换到 footer 上，行编辑时顶部「保存/放弃」
状态就失联了（`updateButtons` 操作的是已脱离 DOM 的节点）。

### 5.3 搜索视图

新增按别名搜索：`<field name="alias_ids" string="别名" filter_domain="[('alias_ids.name', 'ilike', self)]"/>`。

## 6. Excel 导入导出

### 6.1 导出（`/plm_product_category/export`）

表头由 6 列变 7 列，「别名」放在「产品Ⅳ级分类」之后：

| 产品Ⅰ级分类 | 产品Ⅱ级分类 | 产品Ⅲ级分类 | 产品Ⅳ级分类 | 别名 | 已关联料号数 | 有效性 |
|---|---|---|---|---|---|---|

别名多值用英文逗号 `,` 拼接，空别名留空。

### 6.2 导入（`/plm_product_category/import`）

| 步骤 | 逻辑 |
|---|---|
| 列校验 | `ncols` 由「必须等于 4」放宽为「等于 4 或 5」；4 列视为旧模板，无别名 |
| 别名拆分 | 第 5 列按 `[,，]`（英文/中文逗号）拆分 → 逐个 `strip()` → 去空 → 保序去重 |
| 路径校验 | Ⅰ级必填、不允许跳级，规则完全不变 |
| 新建路径 | 批量 `INSERT ... RETURNING id` 拿回新行 id（现有代码需加 `RETURNING id` + `fetch=True`） |
| 已存在有效路径 | 分类行不改动，别名**追加去重**：只补库里没有的，绝不删除已有别名 |
| 已停用路径 | 保持现有逻辑（重新激活），别名同样按追加去重处理 |
| 别名落库 | 开循环前一次性 `SELECT name, category_id FROM xc_plm_category_alias` 建内存映射；命中且 `category_id` 是当前行 → 跳过；命中但属于其他行 → 跳过并记冲突明细；未命中 → 批量 `INSERT` |
| 结果提示 | 沿用现有格式，末尾追加「写入别名 N 个，跳过 M 个」；冲突明细逐条放 `data` 数组，形如「第 5 行:别名「PSU」已属于 服务器配件/GPU」 |
| 事务 | 任一步异常整体 `rollback`（沿用现有 try/except） |

## 9. 风险与注意事项

| 风险 | 处理 |
|---|---|
| 新增模型未重启服务 → 模型未注册、报错 | 部署步骤强制含重启 |
| 全局唯一约束与中文空格/全角输入 | `strip()` 只能去半角空格；如需去全角空格再补 `replace('\u3000', '').strip()`，本期待验证实际录入习惯后决定 |
| 别名含逗号时导出再导入会拆错 | 导入提示里注明「别名内不要包含逗号」；页面维护不受影响 |
| 未保存行点按钮 | Odoo 先提交当前行，属原生行为，不额外处理 |
| 弹窗关闭不刷新 | 已验证框架会自动 reload，无需处理（§5.2 有源码依据） |

## 10. 被否决方案（留档）

| 方案 | 否决原因 |
|---|---|
| `Many2many` + `many2many_tags` 列内标签编辑 | 建模不正确（一个别名可被多分类共享，需靠关系表唯一索引变通），多一张表且需写孤儿清理逻辑 |
| 主表 `Char` 存「PSU,电源模块」 | 别名含逗号即歧义，无法做唯一校验，无法精确反查 |
| 分类加 `form` 视图、双击进表单维护别名 | 现有列表是 `editable="top"` 行内编辑，双击进表单与行内编辑冲突，且会改变现有操作习惯 |
